# 逐题思考与独立分析

更新：2026-10-12，关联 #250。普通题和情景任务共用持久化作答轮次；PK 保持现有流程。

## 作答与交卷

每题提供默认收起的「我的思考 / 评价」，选填，最多 4000 字。答案与思考自动保存，未同步内容另存本机草稿。整组交卷前可修改，不展示对错、参考答案或答案提示。思考不能替代正式答案。

对话题组、篝火热身、网页共读题、桌面题卡和情景交互均覆盖。共读题保存出题时的材料快照，分析不会因切换网页而引用新页面。

交卷以事务锁定整组答案与思考；有未完成题、过期草稿版本或非法操作值时整组拒绝，保留输入。客观题按标准答案核对；填空文字吻合直接判对，其余填空与解答题交现有阅卷模型。阅卷请求只含题目、参考和正式答案，不含思考。

情景消息只认当前 iframe、demoId、协议版本和任务白名单。交卷前每次操作可更新观察值。服务端从归属套题读取任务规则，不信任客户端提供的规则；交卷时按现有 choice/state/order 判定。沙箱内部由题目作者实现的即时反馈不代表服务端成绩。

## 独立题解任务

每位用户同时最多三道题运行，其余排队；跨题组共享此上限。每题独立完成标准核对、流式分析、图示与迁移自测，较快题不等待较慢题。

文字在对应题下逐步出现，随后补图与迁移题。非空思考分别分析正确步骤、遗漏/误区和题目评价；未填写时略过相关段落。仅传该题内容，不串用其他题的思考。文本不展示模型内部推理。

沿用 solver 角色、统一模型网关、归属配额、超时和调用记录。每题运行上限 240 秒，输出正文上限 24000 字。题解属于学习建议，不更改参考答案和已判成绩。

失败显示在该题下，其他题继续；图示失败时保留正文，重试只补图示。停止保留已生成内容；离开页面不断开后台任务，重开从数据库恢复。服务重启后把未完成任务标为中断，用户可单独继续，不假装仍在生成。重复提交或重试不会重复累计作答与学习事件。

## 历史和隔离

schema v60 新增 quiz_round / quiz_response；不修改已有学习表。每轮保存题目快照、答案、思考、状态、正文和图示。再练一遍产生空白新轮，上一轮保持可回看。

题卡内「作答历史」和桌面设置中的最近记录均可打开历史。未交卷的情景记录可继续操作。用户隔离和会话访问检查与其他接口一致；删除会话时一并清理相关轮次。历史分页每次 20 条。

草稿采用每题版本比较，迟到请求不能覆盖新输入；服务端事件携带全轮递增版本及题目生成代次，旧快照、重复文字和旧任务事件不能覆盖新分析。本机草稿与服务器版本冲突时明确提供恢复后核对。

旧 quiz_stats 继续用于题卡累计记录，新增轮次负责完整历史。普通入口不再由前端重复写作答统计。旧 /api/quiz/explain 保留兼容，但上述入口使用逐题流程。

## 开源参考与取舍

- [LangGraph workflows and agents](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/workflows-agents.mdx)：参考独立 worker 的调度方式；这里以每题为任务，限制并发，不增加整组汇总的等待步骤。
- [Vercel AI streaming data](https://github.com/vercel/ai/blob/main/content/docs/04-ai-sdk-ui/20-streaming-data.mdx)：参考有类型的数据流与稳定标识；这里另加轮次版本和生成代次，支持断线恢复与过期事件过滤。
- [Moodle question attempts](https://github.com/moodle/moodle/blob/main/public/question/engine/questionattempt.php)：参考题目位置、作答轮次与步骤留存；将提交快照和分析分开保存。
- [Hermes grading workflow example](https://github.com/fierro-ltd/hermes-agent-solution-template/blob/main/services/workers/workflows/grading.py)：参考核对、保存与反馈分阶段。它是示例，不作为已验证的生产框架依据。

未引入这些项目的依赖；复用本项目已有模型网关和 SQLite，避免为逐题分析再建立一套模型配置、配额和服务。

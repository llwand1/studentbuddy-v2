# COACH-SPEC — 复习督促小窗 v1.0

> 契约落点：`packages/shared/src/coach.ts`（判定唯一实现）／`packages/server/src/learning/coach.ts`＋`coach-prompt.ts`（域层）／
> `packages/server/src/routes/coach.ts`（六个口 + 一条 SSE）／`packages/web/src/features/coach/*`（UI）。
> 迁移：**v25**（新建 `coach_messages`）。上游：`docs/EBBINGHAUS-SPEC.md`（复习判定与队列）。

## 1. 背景与范围

`EBBINGHAUS-SPEC §7` 把「AI 督促」明确登记为**下一批**。本批落地，形态由老板 2026-09-18 拍板为
**B+C+E 三合一**（不是三个功能，见 §2）。

- **在范围内**：任务胶囊（折叠态）、侧边抽屉（展开态）、卡片流（对话 + 队列 + 复习动作同一屏）、
  主动提醒（服务端判定 + 冷却）、督促 AI 对话（独立链路 + 复习快照注入）、小窗内复习打卡。
- **不在范围内（登记不欠账，见 §8）**：语音、跨设备同步、~~把欠账自动排进学习流~~（⚰️ 宿主 2026-09-25 下线，见 §8 该行）、按领域分别催、
  自动出题打卡、周报。

## 2. 形态：一个组件的两个状态（B+C+E）

老板原话是「可打开和折叠的悬浮小窗」。**折叠态与展开态是同一组件的两个状态，不是两个方案**——
否则要在「打扰」与「能力」之间二选一。

| 代号 | 形态 | 承担的事 | 不承担的事 |
|------|------|----------|------------|
| **B** | 右下角任务胶囊 | 一行数字：`欠 N 条 · 连续 M 天`；欠账时才上色 | 不显示 AI 说的话、不做倒计时 |
| **C** | 右侧抽屉（400px） | 头部账本 + 卡片流 + 输入区，全部能力在这 | 不挤压主区布局（悬浮层，不入 flex 流） |
| **E** | 抽屉内的卡片流 | 队列卡（可翻牌）与流水卡（AI／我／提醒／复习动作） | 不用气泡：动作卡不该被挤成灰色小字 |

- 抽屉与胶囊都**不占主区布局**（不挤压任何页面）；预览面板打开时，两者自动让位到面板左侧
  （CSS `:has(.sb-browser)`，面板为空时不渲染，故该选择器天然只在其打开时生效）。
- 常驻全局（挂在 `.sb-shell` 内、不随 `view` 切换卸载）：卸载会断掉 SSE 与折叠状态，
  用户每切一次页就看到它被重置。

## 3. 数据模型（迁移 v25）

```
coach_messages(id, owner_id, kind, content, meta, created_at)   -- 只追加的流水
  kind ∈ { ai, me, nudge, review }        -- 由 shared/coach.ts 的 CoachCard 决定
  meta = JSON（仅 review 卡用：termId / term / remembered / stage / intervalDays）
```

★ **为什么单开一张表，不塞进 `sessions`／`messages`**：督促小窗不是一次对话，而是长期陪伴流水。
塞进 `sessions` 会让它出现在侧栏「历史对话」里（它不该出现），且 chat 的上下文压缩/截断会拿它当普通聊天处理
（它的上下文另有来源：复习快照）。

★ `owner_id` **可空且无 DEFAULT**：与 `auth/ownership.ts` 的「未登录单人本地模式」同一语义。
给个 `''` 兜底会把「无主」与「空串用户」混成一个值（与 v24 `user_memory` 的取舍**相反**——
那里 `''` 是被 `ON CONFLICT` 的冲突目标列强制的）。

★ **不在库层写 `kind` 的 CHECK**：卡片形态还在长，加 CHECK 就得为每种新卡配一次迁移；
脏值由域层 `parseKind` 归一（落到 `ai`，宁可显示成 AI 卡也不让前端崩）。

★ **打卡复用 `term_review_log`**（复习域的唯一流水），`coach_messages` 里的 `review` 卡只是
**给用户看的动作回执**——两处都写是因为它们回答的问题不同：一个回答"这条词条的复习历史"，
另一个回答"我今天在小窗里做了什么"。数字（stage／intervalDays）取自 `markReviewed` 的返回值，
不在小窗里另算一遍。

## 4. 催不催：判定四条（`shared/coach.ts` 的 `shouldNudge`）

判据是**欠账**，不是时间。到点提醒（"该背单词了"）是闹钟干的活；本功能干的是**把欠账摆到眼前**。

| 优先级 | 原因码 | 条件 | 为什么要有这一条 |
|--------|--------|------|------------------|
| 1 | `empty` | 今天不欠账（`due = 0`） | 没账还去敲门是纯骚扰，也是新用户第一眼的观感 |
| 2 | `cooldown` | 距上次提醒 < 2 小时 | 用户复习时会连续打卡，每打一次弹一次会疯 |
| 3 | `overdue` | 有逾期且最久 ≥ 3 天 | 真欠账，值得打断 |
| 4 | `backlog` | 单条都没逾期但堆到 ≥ 10 条 | 量变引起质变，同样该看一眼 |

- 常量：`NUDGE_MIN_OVERDUE_DAYS = 3`／`NUDGE_MIN_BACKLOG = 10`／`NUDGE_COOLDOWN_MS = 2h`。
- **冷却由服务端把**（`POST /coach/nudge`，冷却期内返回 `card: null` 且**不落库**）：
  靠前端自觉的话，反复开关抽屉就会堆出一串同样的提醒卡。
- 前端**不自己判该不该催**：胶囊红点、抽屉提醒卡、服务端落库判断三处都调同一个 `shouldNudge`
  （判定双写的下场见 `doc-rag.ts` 那次）。

## 5. 督促对话：上下文与模型

**不复用 `/api/chat/*`**：那条链路绑在 `sessions` 上（侧栏历史、压缩、记忆抽取、工具循环全套），
而督促的上下文来自复习快照。硬塞进去两件事会互相污染。

- 上下文 = **人设**（`coach-prompt.ts` 的 `COACH_PERSONA`）+ **快照段** + **近 12 条流水**（`COACH_HISTORY_TURNS`）
  + 本轮提问。快照段里的数字全部来自同一份 `coachSnapshot()`，并明令模型**只能说快照里有的数字**
  （模型极易顺着话题编出"你有 37 个词条"这类数字）。
- 人设与聊天主链路（`chat/system-prompt.ts`）**刻意不同**：那里是讲解老师（篇幅不设限），
  这里是督促员（默认 1~3 句、≤600 字，先给动作再讲理由，不说空话）。
- 模型角色：`coach`（设置页自动多一行，`MODEL_ROLES` 数组驱动）。**未单独绑定则回退讲解模型**
  （`resolveCoachTarget`）——老库升级后 `role_bindings` 里本就没有这一行，若按"必须绑定"处理，
  用户看到的是「该角色还没绑定模型」而他什么都没改过。
- 失败一律给能照着改的错（ADR-5）：没配服务商 / 没绑模型 / 模型报错，三者分开说。
  **用户主动停止不算失败**（不发 `chat-error`、不落"没回上"卡），已吐出的部分照常落库。

## 6. 接口

```
GET  /api/coach/state            快照 + shouldNudge 判定 + lastNudgeAt
GET  /api/coach/messages?limit=  卡片流水（时间正序）+ 快照（开抽屉一次往返拿齐）
POST /api/coach/nudge            主动提醒 → 落一张 nudge 卡；冷却期返回 { card: null, reason: 'cooldown' }
POST /api/coach/send   { text }  发起一轮：立即返回 { ok, card }（我的卡），正文走 SSE
POST /api/coach/abort            停止本轮（中止器按频道键存，只能中止自己的）
POST /api/coach/review { termId, remembered }  小窗内打卡 → 落一张 review 卡
GET  /api/coach/stream           SSE（频道键 coach:<owner>，复用 lib/sse-client）
GET  /api/coach/live             断线重连后的快照对齐
```

- SSE **复用既有事件类型**（`token` / `done` / `chat-error`），不新增事件种类；频道键为
  `coach:<ownerId|null>`，与真实会话 id、PK 的 `pk:` 前缀三者严格隔离（v1 串台教训）。
  「先登记再实现」的登记落点即本文件 §6。
- `POST /send` 前调 `startNewRound(channel)` 清缓冲：seq 按轮从 1 重计，否则前端会把整轮内容去重掉
  （表现为"发了没反应"）。
- 入参闸门：`text` 空 → 400；`termId` 缺失 → 400；`remembered` **必须是真布尔** → 否则 400
  （脏值被 `=== true` 静默当成"忘了"，用户点「记住了」却看到归零是最难查的那种错）。

## 7. 前端呈现

- 胶囊（`CoachCapsule`）：`capsuleLine` 给文案、`capsuleTone` 给配色（逾期红 / 有欠账橙 / 清零灰）。
- 抽屉（`CoachDock`）：状态纪律三条——① 数字只读服务端快照；② 流水以服务端为真相
  （本地只做乐观插入 + 按 id 合并，`done` 后整表重拉）；③ 常连一条 SSE，token 累积成临时卡。
- 卡片流（`CoachFeed`）：**队列在上、流水在下**。默认打开小窗的人多半是来"还账"的，
  先给他能立刻做的动作，而不是先读 AI 昨天说了什么。
- 队列卡**先翻牌再看释义**（默认盖住）：复习的核心是"先自己回忆再对照"，一上来摊开释义等于降级成阅读
  （与 `ReviewPanel` 同一条取舍）。保持率用**分档 class** 着色（gates 禁 `style={{}}`）。
- 时间文案只到分钟：`刚刚 / N 分钟前 / 今天 HH:MM / 昨天 HH:MM / MM-DD HH:MM`，
  解析一律走 `parseCoachTime`（库里的 `datetime('now')` 是 UTC 且无时区标记，直接 `new Date` 会差 8 小时）。

# StudentBuddy v2 · Docker 容器化——构建验证与切换手册

> 版本：v0.1（2026-09-21 起草，**全部步骤未实机验证**）| 依据：老板拍板「先修 daemon，再容器化现有 VPS 部署」
> ★ 红线：本手册任何服务器步骤，执行前先在 `事件登记.md` 记计划条目；每步失败即停，带「回滚」小节。
> ★ 已知前提（实测 2026-09-20）：docker-ce 29.8.1 + compose 5.5.1 已装；`docker.service` failed 三个月，根因 `/etc/docker/daemon.json` 是一行非 JSON 文本；`/var/lib/docker` 424K ⇒ 从未跑过真容器，**清理旧数据无容器损失**。

## 0. 为什么要过三道验证再切流量

1. **better-sqlite3 原生编译**：slim 镜像无工具链，若无匹配 prebuilt 会构建失败或运行 `ERR_DLOPEN_FAILED`——§2 专测。
2. **workspace 解析链**：`server/dist` 把 `@sb/shared` 当 external，运行时靠 `node_modules/@sb/shared → ../packages/shared` 符号链接解析。compose 卷挂载 `/data` 不影响，但**改 Dockerfile 时动 COPY 顺序会静默打断这条链**——§2 的健康检查专防。
3. **双形态并跑**：现网 systemd unit（tsx 或编译态）与容器同端口互斥，切换必须按 §4 顺序，先停旧再起新。

## 1. 修 docker daemon（服务器，5 分钟）

```bash
# 1.1 备份坏文件（保留现场，别删）
cp /etc/docker/daemon.json /etc/docker/daemon.json.bak-$(date +%F)

# 1.2 写入合法配置（内容 = 仓内 tools/docker/daemon.json：json-file 日志 + 10M×3 轮转）
#     先把仓内文件 scp 到 /tmp/daemon.json，再：
cat /tmp/daemon.json | python3 -m json.tool > /dev/null && cp /tmp/daemon.json /etc/docker/daemon.json

# 1.3 启动并验证
systemctl enable --now docker
docker info | head -15
docker run --rm hello-world
```

**回滚**：`cp /etc/docker/daemon.json.bak-* /etc/docker/daemon.json && systemctl restart docker`（坏文件本来就是 failed，回滚无损失）。

## 2. 本机→服务器镜像构建验证（不动线上流量）

```bash
cd /opt/studentbuddy/app        # 仓代码已在的路径；新机器先 git clone
docker compose build server
docker compose up -d --no-dependencies server
sleep 5
# 验证 a：进程活着（没 ERR_DLOPEN / 没 OOM）
docker compose ps server && docker compose logs --tail 50 server
# 验证 b：API + 迁移 + 鉴权闸门（期望 401，非 500）
docker exec studentbuddy-server-1 node -e \
  "fetch('http://127.0.0.1:18791/api/status').then(r=>r.json()).then(j=>console.log(JSON.stringify(j)))"
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18791/api/health   # 期望 200
```

**预言**：首次 `docker compose build` 大概率在 better-sqlite3 节点失败或耗时 >3 分钟（gyp 现编）。若失败 → Dockerfile 第二阶段前加 `apt-get install -y python3 make g++`（builder 阶段编译、slim 只带产物），改完重跑本节。
**回滚**：`docker compose down -v`（**注意 `-v` 会删 sb-data 卷**——本阶段卷里只有测试数据，确认无生产数据写入后再用）。

## 3. 静态资源入卷（server 托 web/dist 的过渡方案）

```bash
# 3.1 起一次性容器把 web dist 拷进命名卷
docker run --rm -v studentbuddy-v2_sb-webdist:/dst -v $(pwd)/packages/web/dist:/src:ro alpine \
  sh -c 'mkdir -p /dst/web && cp -r /src/. /dst/web/'
# 3.2 起 web + 验证
docker compose up -d web
docker exec studentbuddy-web-1 wget -qO- http://localhost:8080/ | head -3   # 期望 <!DOCTYPE html>
```

★ 长期解 = 仓内任务「server 静态托管开关」（#6）：落地后删 compose 里 web 服务与本节步骤。**每次发版要重跑 3.1**（web dist 不随镜像自动进卷——这是过渡方案的税）。

## 4. 切换流量（低峰执行，预计 10 分钟窗口）

```bash
# 4.1 停前登记：事件记一笔「容器切换开始」
# 4.2 停宿主机 Caddy + Node（顺序：先入口后源）
systemctl stop caddy studentbuddy
# 4.3 起容器栈（Caddyfile 需先把现网 /etc/caddy/Caddyfile 拷进本目录，反代目标改 server:18791 / web:8080）
docker compose up -d
# 4.4 验收：五条各就各位
curl -sI https://11wand.com | head              # 静态页 200
curl -s https://11wand.com/api/health           # 期望含 ok
# 未登录业务接口 401 / Secure cookie / Origin 拒绝——按转开放验收清单 B 表 1/2/4 重跑
# 4.5 观察 15 分钟：docker stats --no-stream（内存应 <400M）、docker compose logs -f --tail 20 server
```

**回滚**（任一步不过）：
```bash
docker compose down                            # 不带 -v！数据卷里可能已有新写入
systemctl start caddy studentbuddy             # 回到 systemd 旧形态（代码与库文件都还在原地）
```
★ SQLite WAL 注意：容器停稳后 `data/` 里 `-wal` 应先自动 checkpoint；**回滚前若 wal 有残量，先 `docker compose run --rm server node -e "..."` 或 `sqlite3 /data/studentbuddy.db 'PRAGMA wal_checkpoint(TRUNCATE)'`**，别让 systemd 形态的 Node 撞上未合并的 wal。

## 5. 稳定运行期纪律

- **单实例不变**：`SB_UPSTREAM_SITE_MAX_CONCURRENT` 是进程内 Map（DEPLOY.md §末条），容器化不改变此结论，**别横向扩副本**。
- **发版**：`git pull → docker compose build → docker compose up -d server → 重跑 §3.1`。
- **备份**：cron `.backup` 打的是 `/opt/studentbuddy/data`——切换后改指 `docker volume inspect` 的 Mountpoint，或容器内跑 sqlite3（`docker compose exec server sqlite3 /data/studentbuddy.db ".backup /data/backup.db"`）。**切换当周必做一次恢复演练**。
- README「部署形态不是容器」一句：本手册 §4 跑稳满一周后，按作废登记规矩改文档（不静默删）。
- 转开放验收清单 A 表全部按「容器形态」重跑一遍（env 现在住 compose 文件而非 EnvironmentFile，§4.4 的 B 表项只是抽查）。

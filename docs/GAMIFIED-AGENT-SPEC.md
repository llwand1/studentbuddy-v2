## 1. 一句话叙事（新口径）

**「一个陪你把学习变成游戏的 AI 伙伴：随时来一局（PK）、每天连着练（streak）、看得见成长（XP/段位）、内容拿得出去（分享开放）」。**

- 与旧口径的关系：README 现句「学 → 练 → 析 → 忆 → 反馈 五环闭环」**不删，降级为实现层描述**；对外一句话定位改在 §5 S1 批次里与 README／Landing 同批换，本文不落笔改它们。
- ★ 「agent」这一维**不是新造**：现役工具生态（`TOOL-ECOSYSTEM-SPEC.md` v1.4.6，10 个已实装工具）＋ AI 主动约战（`offer_pk_battle`，v0.2.124 已上线）就是它的底座。新叙事是把「AI 会自己发起学习玩法」从隐藏能力提到台面主打。

## 2. 三个词各拆成可判过/不过的口径

「轻量化／可玩性／开放性」不拆成判据就会变成三个谁都能解释的词。以下每条都能用一次操作或一条查询判定：

### 2.1 轻量化（形态）
| # | 判据 | 现状达标？ |
|---|---|---|
| L1 | 主要学习动作在 **≤30 秒**内完成一轮（一组 5 题卡、一次复习打卡、一局迷你对战） | 部分：复习队列与出题已是短流程；对战是长局 |
| L2 | 移动端（微信内 H5）任一核心玩法**不需要注册第二个账号体系**（PK 复用统一邮箱登录，`AUTH-SPEC §0.1` 口径不变） | ✅ 已成立（v0.2.94 起） |
| L3 | 每批新功能**默认不新增一级导航项**（侧栏维持六项；超出须老板点名） | ✅ 现役六项 |
| L4 | 不做需要常驻后台的重机制（实时联赛、推送服务、匹配队列跨服）——单人运维扛不动，见 [[feedback-growth-metrics-honesty]] 的诚实边界 | 本文即闸门 |

## 4. 明确不做（防「又做重」闸门）

1. **不做实时联赛/全球排行榜**——跨用户实时排名要匹配与反作弊，单人运维等于第二个产品（L4 判据直接判死）。
2. **不做道具墙/抽卡/任何数值付费暗示**——power 保持「补救通道」语义不改（P4 判据：数值必须能由学习行为解释）。
3. **不做原生 App**——形态口径保持 Web H5（`GROWTH-SUBMISSION-PACK` §7.2 对 AlternativeTo 填的真实答案不变）。
4. **不动 PK 计分细则**——战绩体系只做**累加**（跨局聚合），不改单局规则，否则 `settle.test` 一族锁定测试与 1214 行契约全部要重谈。
5. **不把「游戏化」做成第三套数据**——streak/XP 一律从既有行为流水（`term_review_log`、`pk_matches`、quiz 判分）派生，`next_review_at` 式「派生不落库」的既有原则沿用，能少一张表就少一张表。

## 8. S1 施工设计（v0.3.0-rc 新增；老板 2026-09-25 13:2x 定案两格＝「聊天不打卡」＋「两本账收成一本」，随后点头开工 S1-a）

### 8.1 「什么算一个学习日」

`daily_activity.type` 现役四种，S1 起分两档：

| 档 | 行为 | XP | 算学习日？ |
|---|---|---|---|
| 打卡级 | `quiz_answered`（答题）、`quiz_generated`（出题）、`term_added`（词条入库）、**`review_completed`（复习打卡，S1 新增）** | 3 / 5 / 1 / **2** | ✅ |
| 仅计 XP | `chat_done`（聊完一轮） | 2 | ❌ **老板定案：纯聊天不撑连签**（聊天仍涨 XP、仍进近 7 天柱状，只是不算「今天学了」） |

★ 现查前提（这条是 S1 真正的动因，比算法宽严更要命）：**复习今天根本不进活动账**——`POST /api/terms/:id/review`（`routes/terms.ts:163`）只写 `term_review_log`，不发总线事件 ⇒「认真复习一周、没聊天没做题」的账号连签可以是 **0**。S1 补 `review_completed` 事件才谈得上换算法。

### 8.2 周结算算法（把拍板③「当周任 5 天即续」钉成可判过/不过）

- 周＝**周一起**的自然周；`周目标` = 该周学习日 ≥**5**（常量 `STREAK_WEEK_TARGET`）。
- 连签数字 = 从**本周**往前数、连续达标的周里**累计的学习日数**（不是自然日跨度：被宽恕的空洞日不计入数字，但也不清零）。
- **本周永不提前判死**：本周未结束 ⇒ 无论已学几天都计入、且继续向上一周累加；只有**已结束的周**学习日 <5 才断链。
- 沿用既有反逆向激励口径：`今天还没学 ⇒ 不清零`（改前 `computeStreak` 已有此语义，保留）。
- ⚠️ **订正我在会话内口述过的一句**（把握度：高，成文时逐日推演发现）：我说过「按周结算下**周一当天没学、连签照样断**」——**不成立**。按上述定义，周一没学只是数字不涨，断链发生在「某个已结束的周不足 5 天」的那个周一凌晨。要「周一没学就断」得改回**日级严格连续**（＝现状算法），与拍板③的宽口径相互 exclusive。**本契约按周结算实施**；若老板要日级严格，说一句即可，代码改动集中在一个函数。

### 8.3 两本账收口成一本（老板定案）

- `learning/term-review.ts` 的 `reviewStreak()`（只数复习、读 `term_review_log`）**退役删除**，全仓唯一读者 `learning/coach.ts:83` 改读 `computeStreak()`。
- 连带文案两处：`coach-prompt.ts:40`「连续复习 N 天」→「连续学习 N 天」；`shared/coach.ts` `capsuleLine` 与 `CoachDock.tsx:213` 的「连续 N 天」措辞不改（本就不含「复习」二字），但**数字含义变了**，写进本契约。
- 理由登记：复习强度已有「日目标＋队列＋近 7 天柱状」三处外显，第二本 streak 账只剩困惑价值；一本账也符合 §4 第 5 条「不另起第三套数据」。

### 8.4 日键统一为**本地日历日**（S1 顺带修的既有不一致）

- 现查：`activity.ts` 的 `today()` 与 `last7Days()` 用 `toISOString().slice(0,10)`＝**UTC 日**，而复习侧 `reviewStreak`/`markReviewed`/`growth/counters.ts` 都用 `@sb/shared` 的 `localDayKey`＝**本地日** ⇒ 北京时间 **00:00–08:00** 的学习被记到前一天，两本账收口后必须择一。
- 择定：**统一本地日**（与较新的复习／增长侧同口径，且「凌晨背书不该算断签」是复习侧注释里已写明的意图）。
- ★ 代价如实记（不做迁移、老行不回改）：改前写入的 UTC 日键行，其归属在 00:00–08:00 时段差一天 ⇒ 少数夜间用户的连签数字在切换后可能有一次性抖动；不写迁移把这件事藏起来。
- ★ 同批必改一处测试：`routes/settings-tenancy.test.ts:162` 用 SQLite `date('now')`（UTC）断言「今天那一行」，日键转本地后它会在 00:00–08:00 窗口偶发不匹配 ⇒ 改调 `localDayKey`，**不留时段相关的假绿/假红**。

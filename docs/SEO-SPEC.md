## 1. 为什么做

线上定位是演示与试用（见 `DEPLOY.md` 与产品叙事），冷启动靠付费投放不成立。本渠道是免费推广清单里的第 1 项：
**用搜索能命中的讲解页，把「这个产品解决什么」摆到访客面前**，页尾再给一条回主站的路。

三件事按老板 2026-09-22 的拍板定案（不是我的默认值）：

| 决策点 | 定案 | 代价（写清楚，别事后当意外） |
|--------|------|------------------------------|
| 抓取闸怎么开 | `robots.txt` **默认全封，只用 `Allow` 精确开门**：`/$`（首页）与 `/terms/`（词条页）两扇 | 以后应用里新增的客户端路由不会被顺手放出去；代价是**新公开面要记得来改这个文件** |
| 页面写哪类词条 | **学习科学概念 12 页**（提取练习／间隔重复／遗忘曲线／交错练习／必要难度／精细加工／组块／认知负荷／元认知／概念图／费曼学习法／学习迁移） | 搜索量小于「学科知识点」，但**事实可控**：这类内容我们讲得准，也不必承诺学科正确性 |
| URL 形状 | `/terms/<拼音slug>.html`，**带扩展名** | 实测线上 Caddy 对**无扩展名**路径一律 `try_files → /index.html`（`/terms/1234` 与 `/` 返回同一份 SPA 壳）⇒ 带 `.html` 才走静态文件通道。用扩展名换掉一次服务器配置改动 |

## 2. 机制

```
packages/web/src/seo/term-entries-a.ts ┐
packages/web/src/seo/term-entries-b.ts ┘→ term-corpus.ts（唯一事实源：类型＋拼装＋URL）
                                     ↑
                  paths.ts（CATALOG_PATH／PLAN_TOOL_PATH 等地址常量，SPA 侧与构建侧共用）
                                     ↓
                    term-page.ts（纯函数：词条 → 完整 HTML 字符串）
                                     ↓
        ssg.ts::writeSeoPages(dist)  ←─ vite.config.ts 的 closeBundle(order:'post')
                                     ↓
   dist/terms/<slug>.html ×12 ＋ dist/terms/index.html ＋ dist/sitemap.xml
   ＋（批次 H-1）dist/terms/en/<ascii-slug>.html ×6 ＋ dist/terms/en/index.html
   ＋（档位 3）  dist/ebbinghaus-plan.html
```

- **构建期生成，运行期零依赖**：Node 服务端与 SPA 都不参与，页面是纯静态文件，Caddy 直接发。
- **产物随 `deploy.sh` 的 tar 上线**（`packages/web/dist` 在包内），不需要任何服务器改动。
- 页面**不带 `<script>`**，只有一个 `<link>`（canonical）；样式自带一小段，不引 SPA 产物 ⇒ 关掉 JS 也读得到正文。
- 首页壳（`packages/web/index.html`）同时补了 `<title>`／description／og 三件，此前是 `<title>studentbuddy</title>` 裸奔。
- **指向目录页的链接一律从 `paths.ts` 的 `CATALOG_PATH` 拼**（值是 `/terms/index.html`）：SPA 侧（落地页页脚、词条库空态）与构建侧（页内导航、`sitemap`、canonical）共用同一个常量，两侧各写一份必然漂。
- ★ **分享卡（批次 F-3）也走同一个事实源**：`src/seo/og-card.ts` 是卡面文案与 `og:image` 那四行 meta 的**单点**（它从 `term-corpus` 取字段，不另写一份文案），`term-page.ts` 的 `head()` 与首页壳的 og 块都对着它；14 张 1200×630 PNG 落 `packages/web/public/og/`、随构建进 `dist/og/`，重新生成＝`npm run og:shots`。⚠️ **它们是提交资源、不是构建产物**，理由与代价见 §5 第 10 条。
- ★ **英文侧（批次 H-1）另起一套语料、但不另起一套壳**：`term-entries-en.ts` → `term-corpus-en.ts`（类型＋URL＋配对反查）→ `term-page-en.ts`（渲染）→ 同一个 `ssg.ts` 落盘。★ 为什么类型分开：中文侧每一条锁都写着**中文口径**（`productHint` 必须出现「本产品」、description 预算 105 字、`alias` 是英文原名），英文侧一条都不成立——**共用一个类型＝两边各写一半合法字段**；而 `page-shell.ts`（样式与 meta 骨架）**两边共用**，因为样式抄两遍就会漂。★ **配对关系只有一份事实源＝英文侧的 `zhSlug`**，中文侧凭它反查：两边各写一份 hreflang 就会漂，而漂了的 hreflang 不是「少了个标签」，是整簇作废（§5 第 14 条）。
- ★ **工具页（档位 3）是同一条流水线上的第二种页型**：`plan-schedule.ts`（纯函数：起始日＋每日新量 → 逐日行）＋ `plan-page.ts`（渲染，含**页内那段算法** `PLAN_CORE_JS`）→ 同一个 `ssg.ts` 落盘到 `dist/ebbinghaus-plan.html`（★ 根级、刻意不叫 `/tools/…`，理由见本节末那条）。★★ 三条硬约束由 `plan-tool.test.ts` 16 例钉住：**免登录**（它不在 SPA 里）、**不落库**（整页字节里不许出现 13 个网络／本地写入门面词）、**构建期不烘日期**（公开字节里一个 `YYYY-MM-DD` 都不许有——烘一张带今天日期的表进产物＝留一张会烂的表）。★ 关脚本的访客与爬虫读到的是同一张**不带日历日期的形状表**（因此永不过期），带日期的那张只在开了脚本之后出现。
- ★⚠️ **这一层有一个「全仓独一份」的加载约束（档位 3 踩出来的，改这里之前先看）**：`vite.config.ts` 是在**纯 Node**里 import `ssg.ts` 这一层的，而 `packages/shared/src/index.ts` 内部用的是 NodeNext 的 `export * from './sse-events.js'`——Node 找不到 `.js` 文件，于是**任何**从 seo 层 `import ... from '@sb/shared'` 的写法都会让 `npm run build` 红在配置加载阶段。★ 而 CI 只跑 `npm run check`（tsc／eslint／vitest／gates，**不含 build**）⇒ 这一族破坏本地全绿，直到 `tools/deploy.sh` 才炸。⇒ **正解＝取产品事实走子路径 `@sb/shared/ebbinghaus`**（shared 的 `exports` 已加这一条；它自身零 import 所以能单独加载），并且 `plan-tool.test.ts` 第 ⑥ 组会扫「`src/seo/` 非测试文件里出现 `from '@sb/shared'` 即刻红」。**别为了省事把七个复查节点在 seo 层再写一遍**——那正是本册第 42 行那条「两侧各写一份必然漂」在讲的事。

## 7. 维护

- 加一条词条＝在 `term-entries-a/b.ts` 追加一项（**任一文件超 400 行就再开一个 `term-entries-c.ts`**，gates 会拦），`sitemap`／目录页／互链全自动跟上。★ 加一条**英文**词条＝只改 `term-entries-en.ts` 一处（`zhSlug` 是必填项，指向一条真实中文词条，写错即刻红＝§5 第 14 条②）；英文侧同样按 400 行红线预备 `term-entries-en-b.ts`。
- `related` 只写 slug，**写错会立刻红**（`term-corpus.test.ts` 的死链锁）。★ 两边各自只写**同语言**的 slug：英文页的 `related` 指中文 slug 不算 bug 但会红在互链锁上（跨语言只走 `hreflang` 与顶栏那条链）。
- 页面文案改动无需重新部署以外的动作：改语料 → `npm run build` → 发版。⚠️ **改语料要同批重跑 `npm run og:shots`**（PNG 是提交资源，见 §5 第 10 条）——中文卡用 `cjk` 预算、英文卡用 `latin` 预算，越界红在退出码里。
- ★ **发一版要往 `changelog-public.ts` 加一行**（对外口径唯一的手写清洗表；★ 别从内部 `CHANGELOG.md` 复制粘贴——那本里有服务器路径与端口）。加完 `npm run build`，`changelog.test.ts` 会验形状与「版本号在内部账本里查得到出处」；⚠️ **它验不到「你忘了加」，那一条只有人守**（§5 第 13 条①）。
- ★ **新增任何公开面记得同时改 `robots.txt`**：本站是「默认全封、只用 `Allow` 精确开门」，新目录／新文件不放行就是静默不公开；这条与「公开字节不许带内部字样」同由 `public-hygiene.test.ts` 守（它会验 `/changelog/` 与 `/atom.xml` 两扇还在）。⚠️ **`/terms/en/` 是一个"不开新扇"的例外**：它被 `Allow: /terms/` 那扇前缀**顺带**覆盖——省了一行，代价是这层公开性变成"继承来的"而不是"声明过的"，见 §6 第 11 条最后那一条的对账判据。

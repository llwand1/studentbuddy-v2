# 题目自包含评测（`complete`，issue #109）

量的是：联网出题（`generateQuiz` 联网）与现场搜集（`collectQuiz`）交出来的题，**学生只看题卡本身能不能作答**——「阅读材料可知……」没有材料、「如图所示」没有图、「下表」没有数据，都算不完整。契约见 `QUIZ-COMPLETE-SPEC.md`。

- **数据集** `tools/eval/datasets/complete-v1.json`，33 题：13 文段依赖 / 9 图依赖 / 6 表依赖 / 5 无依赖对照。
  - 每题配一道**我（作者）自己检索、自己写的参考题**：20 道出自真实网页（含出处 URL），13 道自编（标 `sources: []`）。
  - 6 张真实图片（Wikimedia Commons，署名与许可见 `datasets/complete-v1/figures/ATTRIBUTION.json`），2 张手绘 SVG。
  - 生成脚本 `datasets/complete-v1/build.mjs`，可重生成。
- **两臂** 跑真实产品代码，评测代码逐字相同：基线＝修复前提交 `1becebb`（独立 git worktree）；本分支＝本 PR。被测模型与视觉角色都是 `agnes-2.5-flash`（`https://apihub.agnes-ai.com/v1`）。
- **评审员** `agnes-3.0-flash`（带图）只看「学生会看到的卡面」（题干／材料／图／选项），判能否作答并盲选答案；另配一个**冻结**的正则检测器（不随产品正则改动）。评审员对 33 道参考题同样打分——那是评审员自己的标尺：**参考题应当全部自包含**（实测 32/32，见下；另 1 道 `F02` 的图片请求返回 HTTP 400，未判出）。
- **搜索快照** 评测沙箱出口在境外，产品的 Bing RSS 通道对它返回与查询无关的结果，DuckDuckGo／搜狗／百度均被反爬拦截。所以由我为每题挑真实习题页、冻结成 `complete-v1.search.json`，评测时在 fetch 层回放（`tools/eval/lib/search-replay.mts`，两臂共用，产品代码零改动；**网页正文仍实时抓取**）。只有 17/33 题有习题页，所以「搜集」列只对这 17 题有意义，且是「搜对了页面」的乐观情形。
- **补跑规则**（两臂相同）：模型偶发输出非法 JSON 或摘录不出题时产品报 `parse`；出题通道补跑 1 次、搜集通道补跑 2 次；HTTP 429／5xx 一律视为传输失败，退避后整条重跑（限流被产品吞成 `parse` 会把限流算成模型不行）。
- **运行**：
  ```
  # 本分支（Node ≥ 22）
  export SB_EVAL_BASE_URL=https://apihub.agnes-ai.com/v1 SB_EVAL_API_KEY=… SB_EVAL_MODEL=agnes-2.5-flash SB_EVAL_VISION_MODEL=agnes-2.5-flash
  npm run eval -- complete-gen --arm fix --resume
  # 基线：git worktree add ../base 1becebb，复制 tools/eval/{runners/complete-gen.mts,lib/search-replay.mts,datasets/complete-v1*.json} 与
  # packages/server/src/learning/complete-eval-metrics.ts 进去，然后同一条命令 --arm base
  # 评分（评审员配置用 SB_JUDGE_BASE_URL / SB_JUDGE_API_KEY / SB_JUDGE_MODEL / SB_JUDGE_VISION=1）
  npm run eval -- complete --base tools/eval/reports/complete-gen-base.json --fix tools/eval/reports/complete-gen-fix.json
  ```
  逐卡明细写到（gitignored 的）`tools/eval/reports/complete-detail.json`；`--replay` 只读评审缓存、零额度重算。

## 怎么读这张表（先说不能说什么）

**单次运行、每个 case 只跑一次。** `agnes-2.5-flash` 的输出随机性很大：搜集通道同一用例前后几次跑，交付数能从 0 变成 10（见下「运行间波动」）。下面只写这次读数**能**支持的结论，别的一律标为没测出来。

**能支持的**

1. **搜集通道：产品不再把「如图……」的悬空题当成可用题交出去。** 基线交付 33 道，评审员判 7 道不能作答（6 道是 `F03` 食物网的「如图……」，图根本没抓）；冻结正则判悬空 6/33（18.2%）。本分支交付 19 道，正则悬空 0/19，评审员判自包含 18/19（94.7%）。被拦下的候选在预览里 `ok:false` 并写明原因（「题干依赖图（题干写着“如图”），但没能从页面取到」），用户看得见，不是静默消失。
2. **出题通道：确定性正则的悬空率 3/93 → 0/94，对照组零误杀。** 无依赖对照（C01–C05）本分支 15/15 自包含、被闸门剔除 0/15。闸门总共剔除 3 道、给 4 道补了 `material`；干净的批次零额外模型调用。
3. **没有拖累答题正确性。** 盲解与标答一致：出题 95.1% → 96.8%，搜集 80.8% → 93.8%（分母都不大）。

**没测出来的（如实）**

1. **出题通道的自包含率两臂没有可分辨的差别**（97.8% vs 97.9%，n≈93）。`agnes-2.5-flash` 自己出题时大多会把材料写进题干（「Read the following passage and…」），基线在这个模型上本来就 97% 以上，天花板效应。这个数字不能拿来宣称「出题变完整了」。
2. **搜集通道的「有可用题的 case」没有变好，反而 5→3，每 case 可用题 0.79→0.55。** 原因主要不是闸门误杀，而是这次采样里本分支几个用例（`P13` 英语阅读、`F03` 食物网）摘录直接 `parse` 失败、`F01` 的题干被模型改写过未过逐字锚点、`F02` 的页面这次抓取失败——都是模型/站点的随机性，但**这次的读数就是这样**，没有理由把它说成进步。
3. **原图搬运在最终这次采样里没有成功交付任何一张图**（「图依赖 case：交付题带图率」＝无分母）。搬运的机制有单测覆盖，也在调试过程中的采样里真实跑通过（`F01` 两道题带上了页面原图，是真实的气温曲线降水柱状图，`F02` 带上了电路图，评审员看图后判自包含），但那几次采样的记录被后来的修复后重跑覆盖，**不计入本表**。
4. **评审员与被测模型同厂商**（`agnes-3.0-flash` vs `agnes-2.5-flash`），有偏好风险；评审员对「记忆型事实题」的立场曾要校准（见下），校准后两臂都用同一版提示词重评。
5. **本分支交付的 19 道里仍有 1 道悬空**（`P06`「According to the passage, why did Columbus go to Lisbon?」，网页摘录把选项黏在了题干后面，闸门把选项文字误算成「内联材料」而放行）。这是看这张表时才发现的漏洞，已在检测器里修掉并有单测，**没有重跑**，所以上表仍是 1/19。
6. 正则检测有盲区：没有引用措辞的隐式依赖（`F01` 的「关于该地气候类型……」，图在别处）基线交付了、被评审员判为不能作答；本分支这次采样没交付它（逐字锚点没过），但调试过程中的前一次采样交付过，同样被判不能作答。只有评审员能量到，产线没有这道检测（契约 §4，§8 已声明不做）。

## 评测过程中发现并已修掉的问题

评测不是只用来打分——它抓到了实现里的四个真 bug，修复与单测都在本 PR 里。前三条修完后整条搜集通道重跑过（上表是重跑后的读数），第四条是最后看表时发现的，没有重跑：

| 发现 | 症状 | 修复 |
|---|---|---|
| 模型把 `figures` 写成 `["[图1]"]` 字符串而不是整数 | 原图一张都搬不了（`figuresSeen=3, attached=0`） | `parseFigureNumbers` 容忍数字／数字串／`[图N]`／`图N`；另加「图紧贴在题干前面」的窄兜底 `adjacentFigureBefore` |
| 题库站占位图（360×360 的「图片加载失败」gif）被当成题图搬了 | 评审员看图后判「图里没有生物名称」 | 下载到 gif 一律不当题图；懒加载属性（`real_src` 等）优先于占位 `src` |
| 网页摘录把选项黏在题干后面（「…? -A. … -B. …」），选项被算作内联材料，「According to the passage…」被放行 | 见上「没测出来的」第 5 条 | 切掉黏在题干里的选项再算内联材料（**未重跑**） |
| 英语阅读题「The writer thinks that ____」没有 passage 字样，正则放行 | `P13` 有 3 道无材料的悬空题被交付 | 检测器加英语阅读固定问法、`paragraph one`、语文「画线句／加点字」 |

另有一次评审员校准：第一版提示词把「需要记忆的事实题」（2023 年 GDP、某诗下一句）判成不能作答——这不是我们要抓的缺陷。改成「只要题干没有指向题卡外的材料，事实/知识回忆题算能作答」后，两臂全部重新评审（评审缓存的键包含提示词哈希）。

## 运行间波动（为什么上面全部要加「这次」）

同一批用例、同样的代码，在调试过程中我重跑过几次搜集通道，交付数互相差别很大（例：本分支的 `P13` 英语阅读在相邻两次采样里交付了 10 道和 0 道，取决于模型这一次是否输出可解析的题集）。所以**不要用这张表的搜集列做精确比较**；它证明的是「悬空题被拦下、拦下的带原因」，不是「产量」。要得到能比产量的读数，需要每个 case 重复多次取平均——本次没做（额度与时间），列为后续。

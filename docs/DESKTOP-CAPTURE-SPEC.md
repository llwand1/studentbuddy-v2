# 本机能力核对、悬浮快问与截图提问

本地桌面构建 0.2.195，保留 0.2.194 的文件工作区与任务中心。

## 修正“独立服务器所以不能读文件”的回答

复现记录是用户问“你能看到我的桌面吗”，默认开启的联网开场强制调用 `search_web`，最终回答按普通云端聊天解释权限，没有核对本机工具。文件 API 已连接，但路由与运行环境说明不充分。

现在本机文件/能力问题首轮强绑 `desktop_workspace`，读取真实工作区、只读/可写边界和桌面目录等元数据，不读取文件正文。普通新闻问题仍按原来的联网开关检索，Grill 模式保留原来的优先级。桌面版发送图片时不强制搜索图中文字；明确的检索任务仍可调用搜索工具。

模型提示词明确区分远端模型推理与本机工具执行、桌面文件与屏幕画面、已有结果与未读取内容，旧回答的“完全没有文件权限”不能覆盖当前运行事实。原生启动器传递 Windows Known Folder 的实际桌面/文档路径，支持目录重定向；文件页增加“打开桌面（只读）”入口。

## 悬浮快问

- 鼠标在收起的吉祥物上方时出现一排“输入提问 / 截图提问”。这是独立不抢焦点的原生小窗，不放大 64px 球窗，不破坏点阵裁剪和透明空隙。
- 菜单夹在当前显示器工作区内，顶部贴边时放在球下方；鼠标可跨过间隙移入菜单，移开约 350ms 后隐藏。拖动、展开、隐藏、崩溃重建或截图过程中不显示。
- “输入提问”展开现有 App，返回当前对话、展开折叠输入区并聚焦，不新建或清空会话。
- 主窗口和展开小屏工具栏另有“▣ 截图提问”，仅原生宿主显示。

## 截图流程

```text
用户点击截图 → 隐藏本应用窗口/吉祥物/菜单/拖尾
  → 本机一次性截取 → 拖动选择区域（反向拖动也可）
  → 本机预览 + 可输入问题
  → 放入原对话的输入框 → 用户点击发送
  → 现有视觉模型蒸馏 → 主对话回答
```

- 框选松开即进入预览；`Esc` 取消，`Enter` 截取整个当前快照。支持虚拟屏幕的负坐标，范围夹在实际快照内，至少 6×6 像素。
- 虚拟屏幕超过 4000 万像素时改用当前显示器，限制内存占用。截图最长边缩到最多 2400px，不放大小图；优先 PNG，超过 3MB 时使用 JPEG，仍过大则明确要求缩小区域。
- 编码桥的 dataURL 小于共享图片 500 万字符限制；输入区仍遵守最多 4 张附件。
- 快照、裁剪和编码在本机内存中处理，不自动保存临时截图或修改剪贴板。原生 Bitmap、Graphics 与选择窗口均释放。
- 取消不改变原草稿和已有附件。截图在首次展开 App 之前收到，也会经内存信箱保留至预览挂载；不会因为挂载顺序丢图。
- **预览和“放入输入框”不调用 AI，也不上传。**点击原有“发送”后，截图才传给配置的视觉模型；未配置视觉角色按原有流程显示可修复的配置错误。
- 本机文件的敏感许可继续生效。截图是用户明确选取、预览并提交的图像，不是模型自主扫描敏感文件，也不提供持续屏幕监控或模型可调用的自动截图工具。
- 发送后仍走现有图片会话保存规则，截图作为提问附件保存，重放使用已蒸馏描述而不重复调用视觉模型。

# 对话练习图文复盘
更新：2026-09-30（新增「作答记录」节；2026-09-27 立，关联 #51、#61）。

普通练习与情景题都遵循「作答 → 反馈 → 整组完成 → 一键图文讲解 → 迁移自测」。
不恢复题库、刷题笔记、今日总结。知识大陆与卡牌数值由现有模块管理，本批不发放虚构奖励。
逐题统计只以「作答记录」节那一种形态存在：题卡自己的对错记录，没有列表页、没有分析。

## 普通题
单选、多选、判断按选项集合比对；判断默认正确/错误两项。
填空按空位分别填写，只做 NFKC、首尾空白和连续空白归一化后的文字比对，不忽略大小写、不擅自认定等价式。吻合可标记，其他情况待复核。
填空的输入（2026-09-30，`quiz/FillBlank.tsx`）：参考答案适合逐格打（≤24 格、字母数字汉字占比 ≥70%）时用打字练习式格子（`components/TypingInput`：一格一字、空格与符号替你填好、「提示」按段揭灰字；不开逐格对错），可点「自由输入」换回普通框（换时清空）；整句、满是符号或没有参考答案的空走普通框。两种框交给判分的都是完整字符串，上面的比对口径不变。出题协议同步要求每空只写要填的词或短语本身（≤12 字、不带标点与单位）。
解答题提供输入、提交与参考对照，不自动给对错。无答案的题也归待对照。
整组完成解锁讲解；再练一遍重置本组作答与讲解。

## 作答记录
用户反馈（2026-09-30）：AI 出完题，做了一半刷新页面，做题痕迹全没。处置：**记结果，不冻结卡**。
- 键是出题时的 `quizId`（2026-09-23 之后出的题都随 `[QUIZ]` 登记行带它）；老卡没有 ⇒ 不记、界面与从前一致。
- 每答一题（题卡当场判分之后）`POST /api/quiz/:quizId/attempts { questionIndex, verdict, answer? }`；重开卡片 `GET` 同路径读回。
  verdict 就是题卡的三档判定 `correct | wrong | review`；`answer` 只回显（悬停「上次答：…」），不参与任何判分，入库截 500 字。
- 落库复用 `quiz_stats`（`quiz_id + question_index` 一行、逐题累计，零迁移）：`attempts +1`；答对 `correct +1`、`streak +1`；
  答错 `streak` 归零；待对照只计次数、不动 `streak`。`last_answer` 从今起存 JSON `{v, a}`；题库时代的裸文本老行按 `streak > 0` 推判定。
  两端算这一行用**同一个函数**（shared `applyQuizAttempt`）：前端答完立刻乐观更新，服务端回什么再覆盖什么。
- 卡顶一行「刷过 N 遍 · 客观题正确率 X%（对/答）· 最近 时间」：N = 各题 attempts 的最大值（答一半刷新也算一遍）；
  正确率只算客观题（单选/多选/判断/填空——填空字面没对上的 review 按未对计），解答题排除；一道客观题没答过 ⇒ 不写百分比（不写 0%）。
- 每题标一枚「上次 ✓／↗／◇」（与反馈行三个符号同一套），本轮答过这题后小标收起（反馈行就在下面）。
- 归属：`quiz_*` 是归主表，读写都用 `ownerForWrite`（未登录 = 无主行）。主键不含 owner——别人往我的题号上写回 404（不泄露 id 存在），不覆盖。
- 读不到 / 记不上：各一行说明（读不到「以前的记录没读到」、记不上「第 n 题的作答没记上（页面上的判分不受影响）」），不回滚、不打断答题。
- 与学习事件流（`POST /api/learning/answers` → `quiz_answered`）并行、各记各的：那边是活动流水（不带题号、还原不了卡），这边是可回看记录。
- 刻意不做：不把整张卡冻结成「已答完」的样子（重开就是新一遍，记录只告诉你上次如何）；图文讲解仍只活在当前页面；不做跨题组的统计页。

## 情景题
只接收当前 iframe、正确 demoId、协议版本与任务白名单内的消息。
完成只认 /api/scenario/report 的结果；防重复并发回传，保留首次服务端判定与对应 observed。
回传失败允许重试，不算完成。重开情景重载 iframe、重置连接状态，保留首次判定。
图文讲解包含题干、提示、criteria 与 observed；模型不能据数值索引编造未提供的选项含义。

## 图文讲解接口
POST /api/quiz/explain：共享 QuizExplanationRequest/QuizExplanation。
验证会话存在及归属（不存在/他人/已删同为404）、入参最多20题/总量60000字符；同一请求者并发409。
使用 solver 角色，显式传 ownerId，继承既有配额。最长180秒，客户端取消/断开会中止适配器信号；结束释放占位。
用户资料与系统提示分开；输出纯 JSON，1～6节合并相关题，每题必须被覆盖。
每节含正文、SVG 与读图说明；须有实际图形与文字标签，拒绝脚本、外链、事件、嵌套网页等；不完整自动重试一次，再失败明确报错。
前端先验证 XML 与图形，再经现有 prepareSvg/SvgPreviewCard 净化渲染。支持放大、下载；迁移题参考折叠。
模型解释用于学习，不写回成绩、奖励或参考答案。讲解仅保留在当前打开卡片；作答对错自 2026-09-30 起按「作答记录」节记在服务端，重开卡片是新一遍作答，界面明示。
图文内容的事实准确性仍取决于配置模型；结构闸门保证有图有文、覆盖题目，不等于事实核验。

## 动效与无障碍
生成中像素等待、选项确认、答对亮点、待复盘反馈、完成面板与进度条；有限入场动画，不闪屏。
prefers-reduced-motion 禁用动效；提交状态与错误有可读文字；进度条/输入/按钮有语义标签。
不把动画完成事件当作业务状态，不阻塞键盘作答。

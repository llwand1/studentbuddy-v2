## §1 为什么现有设施算不出这个数（本契约成立的前提）

三条都是 2026-09-23 的**实测**结论，不是推测（取证过程见 `CHANGELOG.md` 同日 08:56 与 09:44 行）：

1. **GoatCounter 算不出 UV**：它的原始 `hits` 表 **0 行**，只剩按天记账的 PV（09-19～09-23 合计 86）。⇒ 「N **人**」里那个「人」字在现有数据上**不成立**。
2. **两个口径对不上**：同一份流量，Caddy 日志里埋点请求实为 **139 次**，GoatCounter 记账 **86**，差 38%（部分归 GoatCounter 的 bot 过滤与会话去重，**差额未逐条核**）。⇒ 拿任意一边当「人数」都是在猜。
3. **我们自己就是流量**：UptimeRobot 952 次／5 天、伪装百度 UA 的扫描器、`ntp.msn.cn` 预取 15 次、referer 垃圾词四个、再加上本仓 `_probe/` 三个打线上的探针脚本。⇒ **不做剔除，任何计数都是假的**（剔除清单的唯一权威在 `GROWTH-CHANNELS.md` §3）。

★ 由此定死一条总口径（凌驾本文件所有条目，与 `GROWTH-CHANNELS.md` §0 第 2 条同一句）：
**只许放宽「什么算一次」，不许改标签、不许灌假用户。** 现有设施算不出人，所以本契约的数**一律叫「次」**；要叫「人」，得先换成能证明个体性的计数（本批不做）。

## §2 写侧：什么算一次

### §2.1 三种真实动作（`GROWTH_ACTIONS` 是唯一清单）

| 动作 | 采集点（HTTP 入口） | 为什么是它 |
|------|--------------------|------------|
| `app_open` | `GET /api/auth/providers`（`routes/auth-github.ts`） | SPA 启动必调（`web/src/main.tsx`），而**关掉 JS 的爬虫永远不调** ⇒ 这个信号白拿，不必猜 UA。⚠️ 它数的是「装载」，**已登录用户刷新同样算一次**。★ v0.2.0 起这一格还多一条约束：发起这个请求的前端代码**必须走 api 出口层**（现 `api.auth.surface()`），否则它天生没有来源——见 §2.5 末段与那条源码锁 |
| `demo_enter` | `POST /api/auth/demo-login` **成功之后**（`routes/auth.ts`） | 「零门槛进来了」是漏斗里最硬的一格。⚠️ 也正是探针污染最重的一格（`prod-pulse` 每几分钟一次），所以它同时是 §2.3 的主战场 |
| `register_done` | `POST /api/auth/register` **成功之后** | 注册要真邮箱 ⇒ 一次是一次。★ 429／409／400 **不记**：被挡住的人没有注册成功 |

★ **刻意不含「词条被写入」**：那条要按 owner 维度算，与这里的 IP 桶**不是同一个单位**，混进一张表＝混两种口径。
★ ★ **计数只写在 HTTP 入口层**（三个采集点全在 `routes/`，`growth/counters.ts` 不被领域函数调用）——这不是分层洁癖，是三条实际后果：
① 体验号的八条种子内容走 `saveOneTerm`（`auth/demo-seed.ts`），**一个请求都不经过** ⇒ 结构上进不了这份账，不靠「记得排除」；
② 探针与真人在**写入侧**就分开，读侧拿到的数不需要理由就能报；
③ 领域内部将来怎么重构（加事件、加批量入口），这份数**不会跟着漂**。

### §2.2 去重键

`PRIMARY KEY (kind, bucket, day)` ＋ `INSERT OR IGNORE`：**同一来源 IP、同一自然日、同一动作，只算一次**。

★ 为什么不是「一个计数器列做 `+1`」：那样「这个数怎么来的」永久丢失，而这张表要能为外报的一个数字**复算**（C10 的判据就是「复算对得上」）；且读改写在并发下要么丢更新要么上锁。代价如实记：表按「IP×动作×天」增长，按 09-23 实测量级（一天十几个访客）**几年到不了一万行**，故不建归档与清理任务。

### §2.3 探针剔除（`isProbeRequest`）

认批次 E 打好的两个标记，**任一命中即不记**：请求头 `X-SB-Probe` 非空、UA 以 `studentbuddy-probe/` 开头。

⚠️ 反向刻意**不**做「UA 不在白名单就剔掉」：那会把真人少计（老浏览器、无 UA 的读屏器）。判据是**认得出自己**，不是认不出别人。
⚠️ 打标≠不污染：探针写进真库的**其它**行（`daily_activity`／`platform_usage` 等）一条都没少，剔除只发生在**这一张表**的写入侧。

### §2.4 隐私形状

`bucket = sha256(盐 + IP)` 前 16 位十六进制。★ **不落裸 IP**：去重需要「同一来源」这个近似，不需要知道是谁。盐存在 `growth_secret`（同库唯一一行，迁移 v41 用 `randomblob` 生成），★ 刻意**不读环境变量**——多一个必配的键就多一处「漏配即静默退化」，而这里的退化方向是「盐变常量＝可枚举」。
⚠️ 连带后果：**从备份恢复库会连盐一起换** ⇒ 恢复后同一 IP 当天再算一次（宁可重算一次，也不谎报历史）。

### §2.5 归因：这一「次」是谁带来的（v0.2.0 起）

★ 一句话口径：**只多记一个 ≤24 字符的渠道名，其余隐私形状一个字不改**——库里仍然零裸 IP、零完整 URL、零 referer 原文。

**链路只有一条**（任何一环缺了，读侧就安静地变成 `direct`，不报错）：

```
静态页／分享链接上的 ?ref=xxx
  → 前端 captureRef：末触写进 localStorage 的 `sb_ref`
  → 每一个 api 请求由唯一的出口层（`lib/api-request.ts`）带上 `X-SB-Ref: xxx`
  → 服务端 normalizeGrowthSource：小写、`[^a-z0-9_-]+`→`-`、去首尾分隔符、截 24
  → growth_action_day.source（迁移 v42，`NOT NULL DEFAULT ''`）
  → 读侧 bySource：`''` 折成 `direct`
```

| 口径 | 定案 | 为什么 |
|------|------|--------|
| 覆盖策略 | **捕获端＝末触**（新 ref 覆盖本地旧值）；**落库端＝先到先得**（同 `ip·day` 那一行的 `source` 不被后来的 ref 改判） | ★ 两个"口径"不矛盾，作用面不同：末触管的是「这台设备**下一次**请求报谁」，落库管的是「**这一行**（= 第一次见到这个桶）归谁」，与同行的 `first_seen_at` 同名同义。写成首触的话，新渠道会被第一个 ref 永久遮掉，读数看起来「这个渠道一点效果都没有」；写成末触覆盖库里的值，则一天里被转发两次的人会被算成「来自最后那个渠道」，而实际把他带来的显然是第一次那个 |
| 取值范围 | **合规任意 slug，不收白名单**（`^[a-z0-9][a-z0-9_-]{0,23}$`） | 渠道台账是要长新的（`GROWTH-CHANNELS.md` C1–C10），白名单＝加渠道得先改代码，而**漏改的后果是新渠道被折进 `direct`、看起来"没效果"**——那是最难归因的一类错（静默）。代价如实记：读侧会出现台账里没有的名字 ⇒ 复盘时人工认（谁写错谁背，不是系统背） |
| 采集点 | **只认请求头**，服务端**不读 `?ref=` query** | 归一必须**两侧各做一次**（客户端那次是为了不让非法字符走到 `setRequestHeader` 上抛，服务端那次才是真相）；若服务端也读 query，就有第二套**从不经过归一表**的口径，脏值一路进库 |
| 非法输入 | **归不成合规值就当没有**（中文渠道名「贴吧」→ 空串 → `direct`），★ 不折成 `--` 那种假 slug | 折成假值＝凭空造一个永远涨不起来、也没人认领的渠道，比少一个渠道更坏 |
| 静态页 | 公开词条页／更新页／计划表页**零 JS** ⇒ 唯一通路是**链接自己带 `?ref=`** | 由 `packages/web/src/seo/attribution-links.test.ts` 遍历全部公开页锁住：**每页都有一条带自己来源名的回应用链接**（★ 来源名按页登记：词条页与中文目录页＝`terms`、英文侧＝`terms-en`、更新页＝`changelog`、计划表页＝`plan`）、页脚**零裸 `href="/"`**（★ 这条反向锁不是冗余：正向那条两侧同源，`appHome()` 整体坏成返回 `/` 时它照样绿）、且页面上出现的每个 `?ref=` 都要在那份登记表里并过 `^[a-z0-9][a-z0-9_-]{0,23}$`，**观察集合与登记集合双向相等**（多一个少一个都红） |

★ **`app_open` 的采集点必须走 api 层**（`web/src/app/Landing.tsx` 现调 `api.auth.surface()`）。这条是本批真正的修复：头注入只有**一个**出口层，绕开它的那个请求**结构上不可能带来源**，而不是「这次忘了带」。
⚠️ 因此本批破例写了**本仓第一条源码锁**（`attribution.test.ts` 断 `Landing.tsx` 里不含 `fetch('/api/auth/providers'`）——与 `docs/dev/test-plan.md` §7 那条「锁性质不锁实现」相反。理由：**要锁的正是实现位置**，退回裸 fetch 时所有行为测试照样绿。代价也如实写在这：将来把这个请求整体挪去别处时它会误红 ⇒ **连同本条一起改，不许直接删锁**。
⚠️ 归因**不是**绕过探针剔除的通道：带 `X-SB-Probe` 的请求即使同时带了合法 ref 也一条都不记（§2.3 优先）。

## §3 读侧：谁能看、看到什么

`GET /api/growth/counters` —— **公开只读**（老板 2026-09-23 拍板「公开 GET ＋限流」，不挂 `requireAuth`）。

- **理由**：这三个数将来就是要给未登录访客看的，先按公开口径把**限流、响应形状、「0 就返回 0」** 三件事定型；等显示批再补＝拿一个已上线的接口做二次改动。
- **限流**：进程内 IP 桶 **20 次／小时**（与 demo-login／发码同档）。超了 → `429 { code: 'GROWTH_RATE_LIMITED', retryAfterMs }`。★ 只对读限流：这个端点不写库，被刷也只刷 CPU。
- **响应形状**：`{ counts: { app_open, demo_enter, register_done }, unit, unitLabel, firstDay, bySource }`。★ **数字与它的算法一起出门**（`unitLabel` 就是 §1 那句「次（同一来源 IP 当天只算一次）」），否则「前端显示数＝后端可查数」这句话会退化成前端自己编单位。`firstDay` 为 `null` 时是「还没有任何数」，不是 1970-01-01 那种假默认。
- **`bySource`（v0.2.0 起）**：`[{ source, counts: { app_open, demo_enter, register_done } }]`——按 `(source, kind)` 现算 `COUNT(*)`（★ 与 `counts` 同出一张表，不是第二份账），每个来源三键齐全（该来源没做过的动作记 0），排序为**总数从大到小、并列按来源名**（按字面排会把小渠道顶到前面）。★ 两条形状承诺：**库里空 ⇒ 它是 `[]`**（不是三个 0 的假分解行——分解表里冒出一个 `direct: 0` 等于凭空造一个渠道）；**库里的空串在这一层折成 `direct`**（★ 刻意**只在读侧折**：`''` 是「不知道」这个事实，`direct` 是对外报数时的口径，把折法写进库就再也分不出「真直接访问」与「没采集到」）。★★ **不变量：各来源之和必须等于 `counts`**（判据 7）——分解对不上总数就等于两套数并存，那比没有分解更坏。
- ★ **本批页面什么都不画**。真实数为 0 时显示「已有 0 次」是噪音，显示「已有 128 次」是撒谎——两头都不干。**显示与否、挂在哪**（落地页首屏？）是 `GROWTH-CHANNELS.md` C4 那一格待老板点的决策，不在本契约里预设。
- ⚠️ 强制鉴权开关（`SB_REQUIRE_AUTH`）打开时本路径**在豁免白名单里**（`index.ts` 的 `isAuthProtected`）。那是**一个决策不是配置细节**：豁免清单是「必须公开」的名单，加一行等于宣布这三个整数可对外。公开的代价写清楚——暴露的是「有多少人来过」，**不是「谁来过」**。

## §4 已知代价与未决（诚实记账）

| # | 事实 | 后果与判据 |
|---|------|-----------|
| 1 | ⚠️ **未配 `SB_TRUST_PROXY=1` 时 `req.ip` 恒为反代自身地址** | 全站塌成**每天一次**（少计，方向安全）。★ 判据：上线第一天必须核 `app_open > 1`，否则先修配置再看数（同 `routes/auth.ts` 里 `clientIp` 那段注释讲的退化是同一件事） |
| 2 | 「IP·天」是**人**的近似，不是人 | 共用出口的校园网／公司网把多人塌成一桶（少计）；换设备的同一个人算两次（多计）。⇒ 本契约的数**永远不许改叫「人」**（§1 总口径） |
| 3 | 自然日按**服务器本地时区**切（`localDayKey`） | 服务器与开发机同为中国时区，跨零点的会话会被切成两天。不做 UTC：那会让「当天」与访客的当天不一致，且没有更值得的选项 |
| 4 | 记账挂在登录与启动路径上 | ★ 所以 `recordGrowthAction` **永不抛**（内部 try/catch ＋ warn）：计数坏一次的代价应是「少个数」，不该是「进不去应用」。代价＝坏掉时只有 warn 日志，没有告警面 |
| 5 | 三个动作都是**服务端可见**动作 | 落地页滚动、外链点击、词条页停留都数不到（词条页零 JS，见 `SEO-SPEC.md` §5 第 6 条）。⇒ 这份数是「进来了多少人」的下界，不是「看了多少人」 |
| 6 | ✅ **本批已发版（09-23 23:5x），代价条已偿** | 原句「线上表还不存在」在当时为真；v41 已随 `deploy.sh` 第六步在**库副本**上预演（水位 40→41）后切换上线。发版后那件第一件事也做了：curl 现读 → **200／三数全 0／`firstDay:null`**，★ 与「不要凭想象认为已经有数」同一条纪律——**零就是零，不兜底、不美化** |
| 7 | ⚠️ **v0.2.0：同 `ip·day` 那一行的来源是「先到先得」，不是「这一天的最后一次接触」** | 一个人先被 `direct` 记录、当天再从 `tieba` 链接进来 ⇒ 那一行永远留在 `direct`，于是**新渠道被系统性少计**（方向＝少计，不是多计）。★ 为什么不改成覆盖：那一行的语义与同行的 `first_seen_at` 是同一个——「第一次见到这个桶」；覆盖会让「今天这个人来过」在一天里换主人。⇒ **读侧的纪律**：看某个渠道的效果要看**它自己的行数趋势**，不能拿 `direct` 的下降当「归因生效了」的证据 |
| 8 | ⚠️ **v0.2.0：`bySource` 里 `source:'direct'` 那一行含第三方抓取器**（Bing／百度蜘蛛等） | 因为 `app_open` 的采集点是 `GET /api/auth/providers`（§2.1 的选择理由至今成立：关 JS 的爬虫永不点它），但**部分爬虫会直接请求站内页面引用的接口路径** ⇒ 它们的来源被折进 `direct`。★ 本批老板拍板**不换采集点、先用 `bySource` 取证**，所以这是**已知偏差**而非待修 bug。⇒ 判据：`direct` **永远不许被对外解释成「用户直接访问」**；取证要出结论的形状是「除 `direct` 之外的渠道行有没有真的长出数」，而不是 `direct` 的绝对值 |
| 9 | ⚠️ **v0.2.0：归因只在同浏览器内成立**（`localStorage.sb_ref`） | 换设备／换浏览器／清缓存 ⇒ 来源丢失，落回 `direct`；隐私模式下连存储都不可用，本批**已把「存储抛」测成不伤页面**，但那也只是不崩——那次访问的来源就是没了。⇒ 这是「渠道之间横向比大小」的下界口径，与 §4 第 2 条同源 |

## §5 验收判据（可证伪）

1. `curl -s https://11wand.com/api/growth/counters` → 200，`counts` 三个键齐全，`unitLabel` 含「次」且明写去重口径；★ 未发版前该路径应为 **404**（路由不存在），这是「新路由没上线」的判据。★★ **09-24 回标**：该判据已随 23:5x 发版走完——今天现读为 200 且三键齐全（不再是 404），故此后引用本条要连这句一起读，否则会把「404」当成现行事实。
2. **同一 IP 连续刷两次 `app_open` 只涨 1**：连打两次 `GET /api/auth/providers` 后读 `counts.app_open`，与只打一次的差值应为 0（同桶同日）。
3. **探针不涨数**：带 `X-SB-Probe` 或 `studentbuddy-probe/*` UA 的请求（含 demo-login）之后，`counts.demo_enter` 不变。
4. **库里无裸 IP**：`SELECT bucket FROM growth_action_day` 全为 16 位十六进制，且不含任何请求侧字符串子串。
5. **复算对得上**：`SELECT kind, COUNT(*) FROM growth_action_day GROUP BY kind` 与端点返回逐键相等（判据原文：「前端显示数＝后端可查数」）。
6. ★ **显示批（将来）的前置**：页面画出的数必须**同时**画出口径（§3 的 `unitLabel`），且 `counts` 全 0 时**一个字符都不画**。
7. ★ **v0.2.0 归因的复算判据**：`bySource` 里各来源的三个动作分别求和，**必须与 `counts` 逐键相等**（`Σ bySource[].counts.app_open === counts.app_open`，另两键同）。★ 这条是分解表存在的唯一理由——分解不出来就是两套数并存。本地证明在 `growth/counters.test.ts` 与 `routes/growth.test.ts`；线上真跑一次（curl 现读、两侧同数）随本批发版做，未发版前该判据只有本地证据。
8. ★ **v0.2.0 归因的通路判据**：带 `X-SB-Ref: zhihu-blog` 打 `GET /api/auth/providers` ⇒ 库里那一行的 `source` 是**归一后的** `zhihu-blog`，且 `bySource` 里回读出同一名字；★ 反向同测——只把 `?ref=xiaohongshu` 放在 URL 上而不带请求头 ⇒ 服务端**不认它**，那一行落进 `direct`（证明采集口径只有一条，不存在「顺手也读 query」的第二套）。

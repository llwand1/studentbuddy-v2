# 出题配图契约（QUIZ-IMAGE-SPEC）

> 版本：v1.1.1 | 状态：[已落地·真机端到端复验过] | 更新：2026-09-04
> 定位：`[QUIZ]` 协议的**加法扩展**——让模型为需要示意图的题目附带一张 SVG。
> 先立契约再改码（AGENTS.md「已知约束」：超出既有能力预算必须先改契约）。
>
> **v1.0 → v1.1 的教训（必读）**：v1.0 单测 232 例全绿便标 `[已落地]`，但**端到端真机一次没跑**，
> 实际出图率 **0**。根因不在代码链路（数据结构/开关/接口/渲染逐层排除后全部正常），在**提示词层**：
> `svg` 只出现在提示词末尾的追加说明里，`[QUIZ]` 协议的**格式示例 JSON 里没有这个字段**，
> flash 级模型把示例当完整契约，一律不加字段。新增 §2.7「提示词契约」，并更正 §2.6 那条**错误的**风险结论。
>
> **v1.1 的追加教训（本次补做真机端到端才暴露）**：单测 248 例全绿之后，真机又抓到两种
> **单测永远抓不到**的失败——模型自己漏写 `]` 导致整组 502（§2.4），以及模型把提示词里的
> 格式示例方框原样照抄成「配图」（§2.7）。门禁全绿不等于功能可用：**真机跑通、前端画出来**才算落地。

## 1. 为什么做

出题模式此前只有纯文本，几何、物理电路、化学装置、生物结构这类题**没有图就没法做**。
v2 已有完整 SVG 渲染管道（`web/src/lib/svg-utils.ts` 自愈+净化、`SvgPreviewCard.tsx` 渲染卡），
聊天区早已能渲染 ```svg 围栏，但**出题这条线没接上**。本契约只做「接线」，不新造渲染能力。

## 2. 契约内容

### 2.1 数据结构（纯加法，向后兼容）

```ts
interface QuizQuestion {
  // ... 既有字段不动
  svg?: string;   // 新增：SVG 源码，模型自决（需要示意图才给）
}
```

- **老题库完全兼容**：`svg` 可选，历史数据无此字段 → `undefined` → 前端不渲染，**不做数据迁移**。
- **判分逻辑一行不碰**：`answer` / `options` 语义不变，图只是附加展示，不影响正确率统计。

### 2.2 开关（模型自决 + 用户总闸）

| 项 | 值 | 说明 |
|---|---|---|
| 设置键 | `app_settings.quiz_image` | 与 `quiz_mix` 同级，全局一份 |
| 默认值 | `false` | **默认关**。配图会显著拉长输出，弱模型先不背这个包袱 |
| 常量 | `SETTING_KEY_QUIZ_IMAGE` / `DEFAULT_QUIZ_IMAGE` | 落在 `@sb/shared`，前后端共用一份 |
| 端点 | `GET/PUT /api/settings/quiz-image` | 与 `quiz-mix` 同一道 Origin 闸门 |

**双层决定**：用户总闸关 → 提示词明确要求不输出 `svg` 字段；总闸开 → 由模型自决
（提示词写「需要示意图才给，看得懂文字就不给」）。不按题型硬性规定——学科与题型的映射
维护成本高且必然漏，交给模型判断更省。

**v1.1 修正①（总闸必须是硬门，不能只靠提示词）**：v1.0 的「关」只对提示词下命令，
`normalizeQuiz` 根本不看这个开关——模型若仍给 `svg`，关着开关照样渲染。v1.1 起：
**关 → 服务端在 normalize 阶段无条件剥离 `svg`**，提示词只是省 token 的第一道，不是授权判定。

**v1.1 修正②（「模型自决」在 flash 级模型上不出图）**：劝说式负面措辞（「只有当…才画」
「不要为凑数画图」）实测给了模型完全免费的逃逸口 → 一次都不画。细则见 §2.7。

### 2.3 体积与降级（丢图保题）

| 规则 | 值 | 理由 |
|---|---|---|
| 单张 SVG 字符上限 `MAX_QUIZ_SVG_CHARS` | 8000 | 超长基本是模型跑飞了（画了几百个元素的怪物图） |
| 缺 `</svg>` 闭合 | **丢弃** | 宁可不给，也不给半张残缺图——**学习软件里残缺的几何图比没图更糟，会教错**。前端 `fixSvg` 虽能补闭合，但补出来的是截断内容 |
| 不含 `<svg` 根标记 | 丢弃 | 不是 SVG（可能是模型误填了描述文字） |
| 非字符串 / 空白 | 丢弃 | 数据容错（ADR-6） |

**核心不变量：图挂了题必须还在。** 任何一条校验失败都只丢 `svg` 字段，绝不牵连题目本身。

### 2.4 解析兜底（P1 风险的对冲）

一个 `[QUIZ]` JSON 定生死：SVG 里上百个双引号，模型漏转义一个 → `JSON.parse` 抛错 →
**整组 4 道题全丢**。故 `parseQuizBlock` 加一道重试：

**v1.1 的阶梯（`parseQuizBlock`，代价从低到高）**：

0. **前置无损补括号**（`learning/quiz-json-repair.ts`）——见下方「第四种失败」；合法 JSON 上永不触发，故不占一次尝试；
1. 按原样 `JSON.parse`；
2. **失败则把所有 `"svg": "..."` 的值清空**（保留键，不破坏 JSON 结构）再 parse 一次；
3. **截断逐题回退**（§2.6）：找到 `questions` 里最后一个完整闭合的题对象，砍掉尾部残缺那题、补齐 `]}`；
4. 回退后再剥一次 svg；
5. 全失败才返回 `null`（走既有 502 降级路径）。

正则必须能吃掉转义引号：`/"svg"\s*:\s*"[\s\S]*?"(?=\s*[,\]}])/g`（lookahead 找真字段边界；
单纯「吃到下一个引号」会在值内裸引号处停下，残留内容照样非法）。**救援一律单遍线性扫描、
不用 `[\s\S]*?` 那类模式**——这里曾是正则回溯钉死线程的事故点，故另设 500k 字符长度门槛。

**第四种失败：模型自己漏写 `]`（真机端到端复验抓到，单测与 §2.6 那五档截断模拟都抓不到）**：
`finish=stop`、输出一个字没少、`[QUIZ]` 成对、`svg` 键齐全，但写成了
`"options":["A. …","D. …","answer":[0]` —— options 数组漏了收尾的 `]`，整份 JSON 非法，
三道好题被判死成 502（`JSON.parse: Expected ',' or ']' after array element in JSON at position 259`）。
上面 1~4 步全治不了它——它们对付的是「图坏了」和「没写完」，而这是「括号写漏」。

v1.1.1 补 `repairJsonBrackets`：单遍扫字符 + 记容器栈，数组上下文里出现「闭合引号紧跟冒号」
即判定该数组漏了 `]`，把 `]` **插在那个分隔逗号之前**（插在其后就成了 `["a","b",]` 的尾逗号，照样非法）；
若 `}` 撞上未收尾的数组，同样补 `]`，并把 `}` 前悬空的逗号顶掉。该规则**在合法 JSON 上永不触发**
（合法 JSON 里数组元素后只能跟 `,` 或 `]`），故是严格增益，才能当所有尝试的基底。
**末尾残缺不乱补**——那是逐题回退的活，凭猜往下编 JSON 会造出错题。

**v1.1 如实补充（v1.0 只写了机制、没写代价）**：这道救援是**整组级**的——一次漏转义就把
**本组所有题的图一起清空**，题目照常返回，用户界面上一句提示都没有。「丢图保题」成立，
但**丢得无声无息不符本项目 ADR-5（不静默、如实告知）**。故 v1.1 起解析必须产出报告：
`droppedSvg`（模型给了但被规则丢掉的图数）与 `truncated`（是否走了截断回退），随响应上屏。

### 2.5 安全（P0 / P2）

| 级别 | 要求 |
|---|---|
| **P0** | SVG 是模型产出的**不可信内容**，渲染前必须过 `sanitizeSvg`。前端唯一注入点是 `SvgPreviewCard`，**不得另开 `dangerouslySetInnerHTML`** |
| **P0** | `openSvgDocument`（下载/新标签页）入参必须是**已净化**的 SVG——blob 文档继承本应用源，能调写接口 |
| **P2** | **本批新发现并修补**：`sanitizeSvg` 原白名单只剥 script/foreignObject/iframe/object/embed，**漏了 `<image href="https://...">`** —— 模型可借此插外链信标，泄露用户 IP 与本机存在。本批补上 `image` 标签剥除（DOM 路径与正则回退路径都要改） |

### 2.6 输出长度预算

- 适配器兜底 `max_tokens` 8192（`model-limits.ts`，deepseek/qwen/agnes 系显式 8192）。
- 纯文本 4 题约 1.2k~2k token；单张 SVG 实测 300~900 **字符**（真机样本最短 298 字符）。
- 开配图后单次输出实测从 ~700 字符涨到 1.5k~3k 字符，**4 题配置在 8192 token 内**。

**⚠ v1.1 更正：v1.0 此处写的「撞顶表现为截断 → 缺 `</svg>` → 丢图保题，不崩」是错的。**
真机拿实际输出逐段砍尾模拟截断，保留 95%/90%/80%/60%/45% **五档全部返回 null**
（整组题归零 → 路由 502「出题失败」）：截断同时砍掉了 `[/QUIZ]` 闭合与 JSON 右括号，
剥图救援救不回来。**开配图后输出长度 ×2~×4，撞顶概率随之上升**（配比拉到 10+10 几乎必撞），
表现是「整组题出不来」，不是「题在、图没了」。

故 v1.1 新增硬性要求——**截断必须逐题回退救援**：解析器要能识别 `questions` 里最后一个
完整闭合的题对象，丢掉尾部不完整那一题、补齐 `]}`，保住前面完整的题，并把 `truncated`
如实报给前端（与配比缺口同一套「缺了就说什么」的口径）。
权威截断信号用适配器的 `finishReason === 'length'`（不靠猜输出形状）；走了逐题回退也置 `truncated`。

**v1.1 写进提示词的两条长度约束**（它们在契约里，不是提示词风格问题）：

- **每组最多 3 道题配图**，其余一律 `""`。真机最慢一组 96.8s，而适配器无 signal 时有 **120s 硬 abort**；
  20 题全带图不是撞 `max_tokens` 就是被断流，两者都是整组归零。限流是唯一能线性压住这个尾部风险的手段。
- 单次输出实测最长 5314 **字符**（8192 token 预算内），但这是 4–5 题配置；配比拉高时必须同步重评。

### 2.7 提示词契约（v1.1 新增，flash 级模型的实测结论）

配图功能**能不能出图只取决于提示词写法**，与代码无关。真机对照（同一模型
`agnes-2.5-flash`、同一材料，自变量只有提示词）：

| 变体 | 做法 | 结果 |
|---|---|---|
| v1.0 现状 | 示例 JSON 无 `svg`；配图说明追加在**末尾**；措辞「只有当…才画 / 文字说得清不要配图 / 不要为凑数画图」 | **0 图**（模型反写出「根据图示…①」「（见配图②）」——认定有图，就是不产出字段） |
| V2 | 只在示例 JSON 里加一个 `svg` 示范字段 | **0 图** |
| V3 | 示例加字段 + 「至少 2 道必须配图」硬性要求 | **0 图** |
| **V4（采纳）** | `svg` 写进**字段清单 + 示例**；口径改**正面强制**（凡题干涉及如图/图形/结构/装置/几何体/图像/受力/光路的题必须给；不需要的给 `""`）；属性**用单引号** | **出图**（2~3 张/组，JSON 一次合法） |

四条硬要求（缺一不出图）：

1. **字段必须出现在格式说明与示例里**——小模型照示例办事，追加在末尾的说明压不过示例。
2. **口径必须正面强制**——「文字说得清就不要配图」这类劝说式负面措辞等于送模型免费逃逸口。
3. **必须给「不需要配图」的合法出口**（`"svg": ""`），否则模型在不必配图的题上会硬凑或整段放弃。
4. **SVG 属性一律单引号**——把 JSON 串内转义引号的坑从源头掐掉（§2.4 的整组清空救援因此很难再触发）。
   已核 `web/lib/svg-utils.ts`：主题色替换 / 宽度钳制 / viewBox 合成的正则都是 `["']` 双写法，
   单引号属性完全兼容，不会漏色或漏钳。

**两个必须如实记账的代价**：

- **耗时**：同材料 3.6s（纯文本）→ 5~29s（带图），输出 ~700 字符 → 1.5k~3k 字符。
- **中转按 prompt 缓存**：`api.agnes-ai.cn` 相同提示词 8/10 次以 0.1s 返回**同一份**结果。
  做统计/回归时必须换材料或加 nonce，否则测的是缓存不是模型（v1.0 若跑过一次真机也会被它骗）。
  本批最早那轮 10 次统计（`stat-result.txt`）就是这样**作废重跑**的。

### 2.7.1 改后实测（V4 口径落地后，全批换材料破缓存）

探针版 V4 口径，8 组不同学科材料（`stat2-result.txt`，配比单选 3 + 填空 1）：

| 指标 | 实测 |
|---|---|
| 一次 `JSON.parse` 就合法 | 8/8 |
| 出齐 4 题 | 6/8 |
| **至少 1 张图** | **7/8**（v1.0 同口径为 0/8） |
| 图总张数 | 18 张（平均 2.3 张/组） |
| 耗时 min/avg/max | 5.2 / 27.4 / 96.8 s |
| 单次输出最长 | 5314 字符 |

生产提示词（`QUIZ_PROTOCOL` + 3 张限流 + 不照抄条款）真机三组：

| 材料 | 结果 |
|---|---|
| 传送带（`e2e-on.mjs`） | HTTP 200 / 7.3s / `images={on:true, delivered:3, droppedSvg:0, truncated:false}`，4 题 3 图，fill 题正确留空 |
| 伏安法 + 斜面（`e2e-keep.mjs`） | 4 题 3 图（svg 长 3537 / 1345 / 2447 字符）；**前端逐张目视**：电路图、接反对比图、斜面受力图均为真矢量图，填空那题无图 |
| 机械波 | 第一次 502（漏括号，§2.4 第四种失败）；补 `repairJsonBrackets` 后同材料重跑→4 题全解析 |

收尾复验再加一批（`stat-prod.mjs`，5 组全新学科材料、`save:false` 不落库）：

| 指标 | 实测 |
|---|---|
| 接口成功 | 5/5 |
| 出齐 4 题 | 5/5 |
| 至少 1 张图 | **5/5**（1~2 张/组，共 8 张，均 **1.6 张/组**） |
| 照抄示例方框 | 0 例 |
| `droppedSvg` / `truncated` | 全 0 |
| 耗时 | 4.7 / 11.2 / 24.3 / 26.6 / 30.1 s |

★ **但出图率不是 100%**：同一轮收尾里另一次端到端跑「凸透镜成像 + 高锰酸钾制氧气」材料，4 题**一张图都没给**
（HTTP 200、`delivered:0`、`droppedSvg:0` —— 是模型自己没产出，不是被服务端规则丢的），
而「光路／装置」两个触发词都在提示词的硬性清单里。合并本批生产口径 6 组：**5/6 至少 1 张图**（与探针 7/8 一致）。
结论要如实说：**配图是「大概率有、偶尔没有」，不是保证**——界面靠 `imageNote()`「本组没有配图」那一句如实告知，
不拿「开关已开」冒充「图已交付」。若要更高保底率，得改拍板过的方案（两阶段补图或重试，见 §4），不属本批。

**照抄示例的坑（v1.1.1 修）**：格式示例里那个 `<rect …/><text>A</text>` 方框被模型**原样抄进**
了本该画真图的题——实测一组 3 张图里 2 张是同一个方框，属于「有字段的假配图」，
比没图更坏（学生看到的是空白方框）。修法：规则行明写「示例里那个方框只是演示字段怎么写，
照抄进题目等于没配图」；加条款后那组三张图各不相同且切题。
⚠ 样本量小（改前 1 组、改后 2 组），**只能记为已观察到的风险 + 已加条款，不能当作已消除**；
探针那 40 张图里 0 张照抄（探针示例结构与生产不同），也不构成反证。

## 4. 未做（显式划界）

- **不引入图片生成模型**：SVG 由出题模型顺手写，不新增依赖（保持 @sb/web 零运行时依赖）。
- **不支持位图**：只收 SVG。位图要占存储、要上传、没法主题化，本地单用户形态无收益。
- **不给老题库补图**：历史题不回溯重跑（要补图请重新出题）。

- **不改成两阶段补图**：仍按已拍板的「字段加法」。两阶段（JSON 只留 `figure` 标记、SVG 走
  `[/QUIZ]` 后的独立块）实测也通且快得多（6.8s vs 28.7s），但它推翻 09-04 已确认的实现路径，
  要改得先回契约重新拍板。
- **不自动重试**：一次出题失败不默默再抽一次（费时费额度）；只把真因说清楚，重试交给人。
- **不修模型侧网络异常的呈现**：真机复验期间撞上一次 LLM 请求 `fetch failed`（中转/网络抖动），
  现以 **HTTP 500 + `"error":"fetch failed"`** 原始文案冒到前端，与「出题失败可重试」不是同一条路径。
  属既有 LLM 错误处理缺口，与本契约无关，**未纳入本批**（改法：路由 catch 后归一成 502 那句可重试）。

### 踩坑（均已修，沉淀进 test-plan §7 约定）

1. **三元假分支静默保留原值**：`normalizeQuiz` 初版写 `push(svg ? {...q, svg} : q)`——坏图分支什么都没做，非法 svg 被原样留下，5 例测试红 4 例。正确写法是坏值时 `const { svg: _dropped, ...rest } = q` 整字段删除。
2. **截断判据写错**：`normalizeQuizSvg` 初版只认 `</svg>` 判终止，把自闭合 `<svg .../>` 误杀。截断的判据应是「两种终止写法（`</svg>` 与自闭合）都没有」。
3. **剥图重试正则**：单纯「吃到下一个引号」会在值内裸引号处停，残留内容照样非法；改用 lookahead `"svg"\s*:\s*"[\s\S]*?"(?=\s*[,\]}])` 找真字段边界，并加 500k 长度门槛防回溯。
4. **`droppedSvg` 漏报最该报的那种**：初版只在 `normalizeQuiz` 里计数，可走「剥图重试」时 svg 已在 JSON 文本层被清空，进到 normalize 前根本看不见。修法：每次尝试带 `stripped` 计数并累加进报告。
5. **`truncated` 靠输出形状猜不出来**：抽取用的贪婪 `\{[\s\S]*\}` 已把残缺尾巴吃掉，`prefix.length < json.length` 恒 false。修法：走了逐题回退即置 `truncated`，真截断另由适配器 `finishReason === 'length'` 提供权威信号。
6. **补 `]` 的位置**：插在分隔逗号**之后**会得到 `["a","b",]`，仍是非法 JSON；必须插在逗号之前（`}` 前那个悬空逗号则直接被 `]` 顶掉）。第一版就因此测不动，3 例红。
7. **复验产物别用固定文件名**：探针按 case 名写盘（`probe6-机械波.txt`），重跑同一材料把上一份**唯一的真机坏样本覆盖了**。复验样本必须带时间戳或不同名，否则证据会被自己冲掉（本次只留下了单测里那份逐字结构的 fixture）。

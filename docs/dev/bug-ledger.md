## 字段说明

| 字段 | 含义 |
|------|------|
| **收敛计数** | **首位字段**。「AI 声称修复 → 客观验证/复现失败」累计轮数；1=正常修／2=必须换根因假设／**3=强制切换策略，禁止第 4 次同向尝试**。**不按**改动次数、提交次数、对话轮次计数 |
| 症状 | 观察到的问题（一句话） |
| 报告版本 | 发现时所在提交（`git rev-parse --short HEAD`） |
| 预测根因 | 修**前**猜测的根因，具体到 `文件:行号 / 函数 / 机制` |
| 是否猜中 | 用测试或可复现步骤**客观**验证（✔／✘／△部分／未验），不采信 AI 自评 |
| 用的模型 | 做预测与修复的模型标识（防把"模型弱"误读成"架构烂"） |
| 屎山指数 | 同**根因**累计修不好次数（一次修好=0） |
| 升级架构问题 | 指数 ≥ 阈值或判定结构性 → 是/否 + 去向（冻结区 / ADR 编号） |

## 维护约定

1. **只进不删**：修好的条目保留并标「已修/对照」，作"什么不是屎山"的参照；
2. **同根因才 +1**：换假设/换模型后的新尝试不重置计数，但须记 `用的模型`；
3. **触发重写评估**：满足《计划重写文档》§10.2 量化闸门任一即强制评估——**本表只引用不复制阈值**（v2 建立时基线：白写率 1.6%，见 `计划重写文档.md` v0.4.4 §10.2 表）；
4. **体验类 bug**（UI 假死/闪烁/卡顿等写不出断言的）：必须「可复现步骤 + 老板主观确认」**双签**，AI 不得自行验收；
5. **★ 计数必须对 AI 可见**：本表若只由人维护、AI 读不到等于不存在。每次改 bug 开工前强制读对应条目，并把计数写进回复首行（GUIDE §0.15 模板）。

# EXAM-MODE-SPEC — 应试模式与来源白名单

批次 `EXAM-1004`（2026-10-04）。本契约管三件事：**范围怎么定义**（用户勾的考试类目 + 自填域名）、
**在哪一层强制**（六条外部入口同一把闸）、**这份白名单凭什么这么列**（§2 的四条实测）。

## 1. 原提示词留痕（逐字）

> studentbuddy现在出题质量和资源是一个很大的问题,所以现在需要你加一个应试模式,应试模式下用户所能
> 感知到的一切内容都应该是和应试的内容有关,并且应试的范围由用户来决定,就用白名单的形式,只在特定
> 范围内的网站去搜集资料和题库,所以现在就需要你去全力搞一个白名单的第一版,并且实现这个功能

拆成四条可验收的承诺，逐条都有落点（本契约其余章节按这四条编号）：

| # | 承诺 | 落点 | 验收判据 |
|---|---|---|---|
| C1 | 有「应试模式」这个开关，且**缺省关** | `exam_mode` 设置项 | 关时出题提示词、搜索结果、抓页行为与开启前**逐字一致**（`search-scope.test.ts`、`exam-mode.test.ts` 各锁一条） |
| C2 | 模式下用户能感知的外部内容都受范围约束 | 六条外部入口同一把闸（§4） | 六条链路逐条有测试；漏一条就是假承诺 |
| C3 | 范围由用户决定，形式是白名单 | 17 个类目预置包（传统考试 11 / 求职面试 6）+ 自填域名（`exam_sources`） | 设置页勾选即生效；自填域名归一化、非法条数当面报出 |
| C4 | 只在范围内的网站搜集资料**与题库** | `searchWeb` 后置过滤 + 题源站内直达 + 固定入口页（§3 三层） | 范围内零命中时**如实说**，不拿 AI 题冒充真题 |

## 2. 为什么是这么做（四条实测，2026-10-04 本机出网）

这一节是设计的**唯一根据**。任何后续改动若与这四条冲突，先复测再改文档，别改代码迁就旧叙述。

1. **免 key 的 Bing 通道不理 `site:` 操作符**。带 `site:zujuan.xkw.com` 与不带的 10 条 SERP
   几乎逐条相同（三例一致：高考／考研／公教各一次）。⇒ 「在查询期把域限定住」这条路在
   免费通道上不存在，白名单必须**后置过滤**。（把握度：高）
2. **原《题源登记表》8 个站里 5 个抓不到正文**：`zujuan.xkw.com` 0 字、`www.zxxk.com` 0 字、
   `www.jyeoo.com` 109 字、`zujuan.21cnjy.com` 路径 404、`www.shangxueba.com` 连不上、
   `www.khanacademy.org` 403。⇒ 「真题优先」此前多数时候抓到的是壳页，这就是「出题质量与资源不行」的
   「出题质量与资源是很大的问题」的直接机制。（把握度：高）
3. **管道级实测**：11 个应试主题 × `collect` 的三查模式（`X 真题`／`X 练习题 答案`／`X 题库`）
   ＝ 88 条命中，其中 33 条（38%）落进拟定白名单；**逐条下钻后只有 1 条能 verbatim 抽出题目**
   （`aipta.com` 的真题文章页：11129 字正文／11 个问句／66 个选项标记／带答案解析），
   另有 `dongao.com` 题库页可抽（8073 字／4 问句／13 选项）。⇒ **通用搜索引擎不是好题源。**（把握度：高）
4. **题源站自己的检索入口好用**：从各站首页的 `<form action>` 里挖出 9 个可拼 URL 的站内检索
   端点并逐个真打过，落点全在登记域内、返回 13–172 条同域结果链（爱真题／真题营／华图／教习网／
   高考 100／建设工程教育网／正保会计／医学教育网／菁优网）。⇒ 白名单要真能提质量，
   靠的是**站内直达**这一段，不是靠搜索引擎听话。（把握度：高；菁优网那条「结果话术」未证实，见 §5）

## 3. 三层强制

> 2026-10-05 补第 0 层：老板指出「白名单还是太少，而且求职面试、传统考试两类都要有」。
> 实测下来这两类**取材方式根本不同**——传统考试能靠搜索过滤（10-04 读数：11 个主题 88 条命中里
> 33 条即 38% 落在范围内），求职面试不能（10-05 读数：8 个面试主题共 80 条命中，范围内只有
> **4 条＝5%**，落点全是 oracle / runoob / CSDN / 知乎 / leetcode 这些站外域）。
> 而 JavaGuide、小林 coding、面试鸭这类站是文档站，检索在客户端做 ⇒ **拼不出可请求的查询 URL**。
> ⇒ 光靠「后置过滤＋站内直达」这两层，求职面试组等于没做。第 0 层把「打开页面就是几百道题」的长文页**登记成入口**。

```
第 0 层  固定入口页（求职面试组的产出主力）
   EXAM_SOURCES[].entries = 实测「打开就是题目」的长文页 URL，逐条带 verifiedAt
   · 零查询词、零搜索引擎依赖；examEntryLinks() 只判「这站在不在范围内」后原样给出
   · 2026-10-05 真机读数：勾五个求职包 ⇒ 范围内 9 站、入口页 11 条；抓 5 页里 4 页 ★可抽题
     （正文抽取长度：小林 C++ 71087 字 234 问句／Go 57944 字 197／Python 51503 字 382；面试鸭首页 11255 字 39）
   · ★ 取消勾选某个类目，它的入口页必须一起消失——不许因为「这行在表上」就绕过范围

第 1 层  后置过滤（硬边界）
   searchWeb() 合并去重之后按域一刀切 → kept / dropped
   · 保证「范围内」这句话是真的；空 hosts = 全拦，不是不设界
   · 缓存键必须带范围签名（examScopeSignature），否则跨范围/跨用户串味
   · 带范围时每家取回量 6 → 10：过滤会砍掉约六成，按 6 条取回再滤常常只剩 1～2 条

第 2 层  题源站内直达（传统考试组的产出主力）
   examDirectQueries() → 登记表里的 direct 模板填 {q} → fetchPageText() 取检索页
   → directLinksOf() 挑同域题页链接 → 交给 learning/collect.ts 照常抓正文与摘题
   · 只在应试模式开时发；单站 403／超时／JS 壳逐条记 failed，绝不阻断出题
   · 求职面试组这层只有 1 个端点可用（华图题库）——那些站是文档站，检索在客户端做
   · 摘题与 verbatim 锁**只有 collect 那一份**：直达不另建一条出题通道
```

> ★ 两处字数**口径不同**，不是互相打脸：图里那组（cpp 71087／go 57944／python 51503／面试鸭 11255）是
> `fetchPageText` 抽出来的**正文**字数；登记表 `label` 里写的那组（75554／59891／51713）是探针拉的**整页**文本字数。
> 两组都来自 2026-10-05 的真机读数，口径各自标清。

## 4. 六条外部入口的闸口清单（C2 的面）

### 应试搜索的补充检索

聊天 `search_web`、设置页试搜、出题参考和真题搜集共用 `search/exam-search.ts`。
通用结果与登记入口按主题选页，读取正文后才计为命中；再补充站内检索与入口中的相关详情页。
关闭应试模式仍直接走原 `searchWeb`，空范围不发外部请求。

- 入口页按查询相关度排序，并先覆盖不同站点；最多读 6 页。站内查询最多 6 站，
  从入口页和站内结果中再读最多 4 个相关详情页；先读具体内容页，目录只发现链接，
  每批至多两页并将新发现的链接重新排序，整个请求共用数量和时间预算，不遍历全站。
  链接选择结合主题词与明确的学科栏目（如 HashMap 对应集合、线程池对应并发），避免泛化词抢占抓页名额。
- 只有实际读取到正文且检索到相关片段的页面才算结果。复用文档检索的 BM25，
  在全文中取片段，不把登记表上的入口链接或页面开头当作搜索命中。
  英文主题词必须都在片段内；中文词元不足的片段剔除，结果按主题匹配度排序。
  广告、培训报名页不计为学习资料；无关语言的页不占抓页预算。通用结果再多也不能跳过正文验证。
- 单页最多等待 6 秒，补充检索总预算 20 秒，继承调用方取消信号；单站失败保留其它站结果。
- 抓页前与每次重定向前都核对白名单，结果合并后再次过滤与按 URL 去重。
- 范围内无结果时说明已查询所选站点，停止同一轮中仅换措辞的重复搜索；
  所有通道失败时说明本次检索通道暂不可用。不得把未检索的 URL 当作引用。
- 设置页报告包含实际使用的 `entry` / `direct` 来源；出题参考范围账记录实际命中的站点。
- 有用户或平台搜索 key 时，Exa / Tavily 请求带原生域过滤参数，合并后的白名单检查仍保留。
  无 key 时保留免费检索与站内补充；验证码页明确记录无法读取，不当作资料命中。

真题搜集只抓本次检索到的相关页面，不再把固定入口置于主题结果之前。
长文超过 25000 字时按主题检索窗口，完整题干仍须通过原文锚点校验；摘录提示词必须给出本次主题。
应试摘录还要求完整题干逐字命中，选择题所有选项须在题干附近成组出现；不能凭全页常见词把填空题改成选择题再标成原题。
应试搜集复用公共网页读取器的请求身份、逐跳范围校验和编码解码，避免参考能读、摘录却乱码或被占位页替代。
聊天出题在本模式下缺省实时联网，显式 `search:false` 仍可关闭；参考检索跳过 24 小时缓存。
应用添加的番茄钟方向标签保留在题目上下文里，检索使用用户原始主题，防附带标签污染查询。
出题时，已识别的考试或技术主题先与用户已选题源相交（如高考英语只取已选高考题源）；
用户自定义域名仍保留，不扩展范围。站内结果先排主题相关链接，导航不能占满六个候选名额。
学习正文保留题干与答案的段落边界，避免整页扁平化后模型无法逐字摘题。
真题搜集在已验证的相关页中优先题页与问答页；摘录总数受本次题型配额约束，不把整页题库全吐出来。
搜集仍最多保留三页，题源反爬、PDF 与仅含目录的页面仍可能无法摘录，报告如实说明。

| 外部入口 | 落点 | 拦下时用户看到什么 |
|---|---|---|
| 聊天 `search_web` 工具 | `chat/tools/web-search.ts` | 步骤条显示「已按应试范围过滤，剔除范围外 n 条」；范围内 0 条时模型照实说「所选范围内没找到」 |
| 聊天 `fetch_page` 工具 | `chat/tools/fetch-page.ts` | 模型收到「不在范围内，本次不读它」，且被明令不许复述该网址 |
| 出题参考资料 | `learning/quiz-search.ts` | 题组下方一行范围账（`examNote`）：取到几条／滤掉几条／走过哪几个直达站 |
| 真题现场搜集 | `learning/collect.ts` | 同上（`CollectReport.scope`），候选为 0 时 `empty` |
| 找视频 | `sources/video-route.ts` | 白名单没放该站 ⇒ `via:'none'` 并写「所选应试范围内没有这一路的视频源」 |
| 阅读页 / PDF / 截图 | `routes/sources.ts` 的 `authorize()` | 403 并给出范围一句话（架上条目若是开启模式前存的，同样拦） |
| 对战裁判取资料 | `pk/judge.ts` | 静默过滤（裁判面板不展示来源清单，属既有口径） |

**出题提示词**另有一条独立路径：`buildExamPromptBlock()`（`learning/exam-mode.ts`）。
它**不塞进参考资料段**——参考资料段只在联网且搜到东西时才存在，而「出题要与所选范围有关」
在不联网时同样成立。关着返回空串，拼接后的提示词与开启前逐字一致。

## 5. 白名单第一版（`packages/shared/src/exam-sources.ts`）

### 5.0 对话中的范围调整（2026-10-06）

- `read_exam_scope` 按当前账号返回已配置的类目、自填域名、开关和可选类目编号，关闭模式时仍能查看配置。
- `update_exam_scope` 支持增删类目与自填域名、显式替换某一集合和开关调整。未提供的集合保持原值；未知类目、非法域名、超过上限、替换与增删同一集合混用均整体拒绝。
- 修改走现有 `planWrite → 确认卡 → apply`：卡片展示新增、移除与开关差异，拒绝、取消或超时不写库；确认期间原设置发生变更则整批中止，不覆盖新值。归属键与设置页同源，保存为原子操作。
- 成功后的工具结果回读实际范围，前端收到完成步骤后刷新共享范围，使设置、检索及 GrillMe 同步。读取与无改动不弹确认卡。

35 条登记行、17 个类目预置包，**分两大类**（2026-10-05 第二版）：

- **传统考试**（11 包）：高考／中考／考研／大学英语四六级／公务员与事业单位笔试／教师资格与教师招聘笔试／财会／建造与工程消防／医药卫生／软考与计算机等级／视频讲解；
- **求职面试**（6 包）：技术面试／算法与笔试／结构化面试／教师面试／银行国企招聘／校招与实习信息。

★ 原来那个 `it`（计算机／IT）包已经拆掉——它把「软考」和「机试面试」塞进同一个勾选项，正是让人勾不出范围的样子。
★ 7 站登记了 **15 条入口页**（第 0 层），11 站有**站内直达端点**（第 2 层）；两类目在设置页分区显示，
组名与说明由 `GET /api/settings/exam-packs` 下发，前端不抄第二份中文。
每一行带 `note`（实测读数）与 `tier`：

- `question`（题源，21 站）＝ 实测页面正文里确有题干与答案，或有可用的站内检索端点；
- `reference`（资料，14 站）＝ 正文可读但取不到成形的题，只当背景材料。

## 6. 复验方法（这张表是外部依赖，改版即过期）

`direct.verifiedAt` 每行都记着最后一次实测的日期。复验**不在仓内建常驻脚本**（`tools/` 进门禁扫描
会带来一套假账），做法是一次性探针：

1. 逐行发一次真实 GET（首页 + `direct` 端点填一个查询词），记下 HTTP、正文字数、是否出现答案/解析；
2. 判据照 §2 第 3 条的四要素：问句数 ≥3、选项标记 ≥3、含「答案」、含「解析」；
3. 不达标的行：`tier` 降到 `reference`，连续两轮不达标就整行删掉并在本文档 §5 的拒绝表里补一行；
4. 表动的同一批必须跑 `packages/shared/src/exam-sources.test.ts`（它锁结构与落点域，不锁可达性）。

## 7. 数据契约与设置面

- 键：`exam_mode`（boolean JSON，缺省 `false`）、`exam_sources`（`{ packs: string[]; custom: string[] }`）；
  两把都是 `app_settings`，**每用户一份**（v30 归主）。★ 写成全局单例的后果：A 开应试模式会把 B 的搜索一起闸掉。

- REST：`GET /api/settings/exam-packs`、`GET/PUT /api/settings/exam-mode`、`PUT /api/settings/exam-scope`；
  写操作一律**回读实际生效值**（归一化与钳位在服务端做，前端不另算一份）。

  挂在 `QuizSearchReport.scope` 与 `CollectReport.scope`（都是可选字段，历史 payload 无此键 ⇒ 旧数据照常渲染）。

## 9. 已知边界（不留隐患式描述，别当 bug 报）

- 后置过滤发生在**合并去重之后**：provider 返回什么就先收什么，再按域砍。所以「范围内 0 条」
  有两种真因（范围内确实没内容 / 每家只取回 10 条不够运气），`dropped` 数能帮区分：
  `dropped` 大 ⇒ 有内容但不在范围；`dropped=0` 且 `kept=0` ⇒ 根本没搜到。
- 站内直达**只做「找到该抓哪一页」**，不判题目质量；质量判据仍全在 `collect-quality.ts` 的
  verbatim 锚点锁上（**这是仓里唯一一把**，别在支路上建第二把）。
- `directLinksOf` 的考试特征词表（真题/试卷/题库/tiku/…）是**白名单之外的第二层筛子**，
  它会漏也会误收；漏了表现为「这一站走直达没拿到候选」，退回通用搜索的过滤结果。
- 阅读页的闸按当前模式判，**不改写历史**：开启模式前存进架上的范围外资料，仍然在资料架上可见
  （点了会被 403），不会悄悄消失——那会让用户以为数据丢了。

## 10. 与既有契约的关系（防漂移登记）

- `docs/RESOURCE-SPEC.md` **D4**（「首版不设白名单，用户指意搜索的返回域即授权域」）：
  由本批**推翻**（后到的明确需求覆盖先前的取舍判断）。原文一字不改，只在原行标注作废与理由；
  撤销登记同时覆盖 `docs/QUIZ-TIER-SPEC.md` §? 的「题源登记表不是白名单」表述——
  它现在多了一个同域的**硬闸**兄弟：`KNOWN_QUESTION_SOURCES` 只管**抓页顺序与真题标签**，
  `EXAM_SOURCES` 只管**范围**。★ 两张表不许互相推断：一张改行不代表另一张也改。

## 11. 词条族的范围联动（迁移 v55，2026-10-05）

老板判决三条：范围只靠**来源站**反推（不加 AI 打标、不做手动归类）、范围外**完全不出现**、XP 与连签**保留全局账**只过滤视图。

**为什么必须新表**：范围是按站点定义的，而知识大陆地块／卡牌／刷词／复习队列的对象是**词条**，两边此前没有连接键。
现查：`term_library` 18 列无任何来源网址，只有 `source_session_id`（会话粒度、N:M，手输／宝箱／开拓／刷词四条路径为 NULL）；本机真库 331 条词条、`message_source` **0 行** ⇒ 借会话反推既给不出「这个词是哪一站喂的」，也没有存量可推。

**形状**：旁表 `term_source(owner_id, term_id, url, host, origin)`，`(term_id,url)` 唯一。走旁表而不是给 `term_library` 加列，理由与 v47 一字不差（`ADD COLUMN` 不幂等，退版本重放的锁会撞 duplicate column）。

**判据只有一份**：`termScopeFilter` 返回**裸谓词**（`1 = 0` 或 `t.id IN (?)`），`applyTermScope`（条件数组形态，词条页用）与 `termScopeSql`（字符串模板形态，大陆／队列／卡牌用）各自加自己的前缀。★ 子句自带前导 `AND` 时与 `conds.join(' AND ')` 拼出双 AND 直接语法错——这条是四个面的测试当场逮到的，不是评审看出来的。

**四个读面**：`listTerms`、`continentMap`、`rowsAll`（复习概览与队列的共同出口）、`cardsByTerm`（卡墙与宝箱同源）。**未过滤**：`listTermsByIds`（按 id 回灌已知词条，过滤会把已经渲染出来的行抽走）。

**空态是必需品不是装饰**：老库升级后 `term_source` 为空 ⇒ 一开模式词条页／大陆／卡墙全空，用户读到的是"我的数据被删了"。`features/exam/ExamEmptyHint.tsx` 三态分开（没勾范围／范围内没词／关着不渲染），并明说「范围外的没有丢，放宽或关掉就能看到」。范围状态由 `useExamScope` 模块级共享一份，设置页写完调 `setExamScopeCached` 广播——三处各查各的会拿到不一致的开关状态（改完设置先刷新的页面对、后刷的页面错）。

**已知代价**：只有从网页侧长出来的词条带来源。对话里 AI 抽的词，若那一轮确实读过页面则记账（`origin:chat`），纯凭对话记忆抽出来的没有 ⇒ 这些词在应试模式下不出现，直到用户从范围内的站再学一次。

# 对话体验（Chat UX）——流式期与常用动作的口径

> 版本：v0.2 | 状态：[活跃] | 新建：2026-09-28（分支 `feat/chat-ux-polish`，叠在 `fix/chat-grimoire-review` 之上）| 更新：2026-09-30（§2.9 空会话直接开聊，分支 `feat/chat-quick-start`）
>
> 本册管的是对话页**流式 UI 与常用动作**的行为口径：错误后怎么重来、键盘怎么停、草稿怎么留、离开标签页怎么知道回答好了、选中一句怎么追问。
> 它不改 SSE 帧（`docs/SSE-CONTRACT.md` 不动）、不改服务端、不加路由、不落库；视觉语言沿用 `docs/PIXEL-UI.md` 的篝火对谈小节。

## 1. 为什么要有它

对话页的流式底座已经齐了（`useChatStream` 的 SSE 重连与 `/live` 对账、`stream-smooth.ts` 的逐字排空、`useScrollAnchor` 的贴底/离底、思考／任务／工具三块过程面板）。缺的是**围绕它的几个日常动作**：

| 场景 | 改版前 | 问题 |
| --- | --- | --- |
| 上游超时 / 断流 / 点了停止 | 只出一条 `⚠ 生成失败：…`，那一轮**没有助手消息** ⇒ 连「重新生成」按钮都没有 | 重来要把问题再打一遍 |
| 生成中想停 | 只能用鼠标去够停止键 | 焦点本来就在输入框 |
| A 会话打了半句去 B 看一眼 | `input` 不随会话切换 ⇒ 半句话跟到 B 的输入框，切回 A 是空的 | 发错会话 / 丢草稿 |
| 长回答切去别的标签等 | 标签页标题没有任何变化 | 不知道好了没有 |
| 离底时底下还在长 | 「回到最新」与看历史时长得一样 | 没有「新内容」信号 |
| 点按钮发送 | 焦点留在按钮上 | 下一句要先点回输入框 |
| 「这句没懂」 | 手抄或整段复制粘贴 | 学习对话里最常见的追问动作没有入口 |
| 第一次打开 / 没选会话（2026-09-30 补） | 输入框能打字却发不出去，建议卡只把提示语填进输入框 | 要先去侧栏「新建对话」、或点卡再点一次发送，「开始页」不是开始 |

## 2. 行为

### 2.1 错误条「↻ 重试」（`ChatErrorBar.tsx`）

- 错误条承载两类错误：**流式中断**（SSE `chat-error` 帧：上游错／超时／`已停止`）与**发送失败**（HTTP 层，`sendError`）。
- 只有前者给「↻ 重试」：那一问已经进了会话，重试＝**对最后一问重新生成**（走既有 `regenerate()`，服务端 `POST …/regenerate`，会保留到最后一条用户消息）。
- 不给的情形：生成中（`busy`，已经在跑）；会话里没有用户消息（没有可重跑的对象）；发送失败（那条提问压根没进会话，改一改再发即可）。
- 点「停止」后留下的半截回答 `（已停止）` 与 `⚠ 已停止` 错误条一起出现——**这是既有口径**，本册只给它一个出口。

### 2.2 Esc 停止（`ChatComposer.tsx`）

- 输入框聚焦、`busy` 为真时按 `Escape` ＝ 点停止键（`onStop`），并 `preventDefault`。
- 不忙时 Esc 什么都不做；输入法组字期间（`isComposing`）的 Esc 属于输入法，不拦。
- 忙态占位文案改为「生成中…（Esc 停止）」——快捷键要**在它能用的地方写出来**。

### 2.3 草稿按会话隔离（`useSessionDraft.ts`）

- 切走：当前输入存到旧会话名下；切到：取新会话的草稿，没有就空。
- 唯一例外：从「无会话」切到刚开的新会话且输入框非空——那半句话本来就是给新会话的，原样带过去。（改版前它承接建议卡「先填字再开会话」；§2.9 之后承接的是「打了半句没发、先点了一张卡」：卡的提示语作为第一问发出，半句话跟进新会话的输入框。）
- **只存内存**（`ref` 里的 `Map`）：刷新页面不保留。草稿是「这一坐」的上下文，不做持久化、不做跨端。
- 既有的「切会话清附件 / 收起载入面板」不变。

### 2.4 标签页标题（`useBusyTitle.ts`）

- 生成中：`document.title` 前缀「● 回复中 · 」；前台完成 ⇒ 复原。
- 后台完成（`document.hidden`）⇒ 前缀「✓ 回答完成 · 」，直到 `visibilitychange` 切回前台再复原。
- 只在「忙过」之后动标题；忙态中途卸载（切页）复原；再次进入忙态先清掉上一段「完成」态——**不叠前缀**。
- 只改标题，**不发系统通知、不响铃**（要授权、也过重）。

### 2.5 离底提示（`ChatComposer.tsx` / `chat-extras.css`）

- 离底且 `busy`：跳底按钮文案「↓ 新内容」＋ `.live`（前面一颗 `steps(2)` 眨的余烬点）；不忙时仍是「↓ 回到最新」。
- 顺手修正：`.chat-jump` 此前 `inline-flex + margin:auto` 从未真正居中，改块级 `flex + fit-content`。
- `prefers-reduced-motion: reduce` 下不眨。

### 2.6 发送后焦点回输入框（`ChatView.tsx` `submit()`）

- 点发送按钮后 `inputRef.current?.focus()`；Enter 发送本来就在输入框里，不受影响。

### 2.7 引用追问（`QuoteAsk.tsx` + `quote-ask.ts`）

- 只认**助手正文**（`.chat-row:not(.user) .chat-bubble.md`，含流式中的气泡）里的选区；用户自己的话、过程面板、题卡里的字都不算。
- 选区侦测：`selectionchange` 去抖 180ms（统一覆盖鼠标拖选、Shift+方向键、触屏拉柄）；至少 2 个非空白字符才算；塌缩 ⇒ 收起；小牌之外 `mousedown` ⇒ 收起；消息流滚动 ⇒ 收起（fixed 定位不跟着选区走）。
- 小牌 `↩ 引用追问` 用 `position: fixed`，横向取选区中点、纵向贴选区底边 +8px；坐标写成元素上的 CSS 变量 `--qa-x/--qa-y`（`style.setProperty`，不走内联 JSX style——门禁红线）。
- 点击：`buildQuote(text)` 逐行加 `> `、丢空行、行内连续空白折成一个空格、超过 `QUOTE_MAX_CHARS = 300` 截断加 `…`；`mergeQuoteIntoInput` 空框 ⇒ `引用块\n\n`，已有内容 ⇒ 接在其后空一行（**不覆盖**打了一半的问题，函数式 `setInput`）；随后聚焦输入框、清掉选区。
- 引用块作为普通 Markdown 进入用户消息（用户气泡按原文显示 `> …`），服务端不做任何特殊处理。

### 2.8 等待时刷词（`features/drill/`，契约 `docs/WAIT-DRILL-SPEC.md`）

- 等待态与刷词的接线只有两根：`App` 已有的 `localBusySid`（发送后 2 秒还非空 ⇒ 弹；变空 ⇒ 「回复到了」）和等待气泡 `Thinking.tsx` 尾部的「刷词」入口（`requestDrillOpen()`，window 事件，不经 ChatView——它贴着 320 行红线）。
- 弹窗是模态：生成期间不能追加输入，✕ / Esc 一键回且本轮不再弹；回复到了**答完这张**再切回（不打断一次作答），不答 8 秒也切。对话页本身的流式、Esc 停止、草稿隔离等口径不变。
- 设置页「等待时刷词」卡可关掉自动弹；关掉后入口仍在。

### 2.9 空会话直接开聊（`useQuickStart.ts` + `Welcome.tsx` + `ChatComposer.tsx`）

**问题**：还没选会话时，输入框能打字却发不出去（`send` 要会话、要 SSE 就绪，发送键按 `blocked` 禁着），建议卡只把提示语填进输入框——新用户第一屏得先去侧栏点「新建对话」、或点卡再点一次发送，才真正开始对话。「开始页」应当就是开始。

- **输入框直接能发**：无会话时 `blocked` 不再等于「未就绪」；回车 / 点发送 ⇒ 这一问（含附图）**暂存**、请 App 开新会话（`onNewSession`）、输入框清空；新会话的 SSE `open` 且不忙时自动发出。`send` 的四道前置门（会话 / 就绪 / 不忙 / 历史已载）**一道不跳**——就绪门由 effect 等，「历史加载中」这一种瞬态被拒（`HISTORY_LOADING_ERROR`，`send` 在任何副作用之前返回它）按 50ms 重试、5 秒内放弃；其余被拒（上游错等）原样进错误条、**不重试**（那时用户气泡已乐观上屏，重发＝发两遍）。
- **建议卡点了就开聊**：提示语作为第一问直接发出（有会话直接发，没会话走上面同一条暂存路径），不再填进输入框。⇒ 四句提示语必须**自足**（它们永远是一段新对话的第一句）：拿不准用户在学什么的，让 AI 先问一句，不写「刚才的主题」这种指望上文的话。
- **开会话期间禁发**：`starting` 为真时输入区 `blocked`，占位「正在开新对话…」；连按 Enter / 连点卡不会开出两间（暂存以 ref 判重）。无会话且不在开会话时占位写明这条路：「问点什么，发送就会开一个新对话…」——**快捷路径要在它能用的地方写出来**。
- **发成功即清暂存，不看 effect 是否已被清理**：`send` 成功会把 `busy` 翻真，deps 变化先触发 cleanup 再回调；若按「已清理就忽略」处理，暂存留到轮末又会再发一遍（同一问发两次）。这条有专门的回归锁。
- **兜底**：App 建会话失败（网络 / 401）⇒ 新 id 永远不来，5 秒后放弃暂存、解锁输入区、错误条说「开新对话没成功，请重试」；视图卸载即丢暂存、清定时器。「+」菜单在无会话时仍整体禁用（出题 / 记忆 / 文档确实都要会话）。
- **草稿不丢**：打了半句没发、先点了一张卡 ⇒ 卡的提示语发出，半句话按 2.3 的例外带进新会话的输入框。

### 2.10 篝火开场题（2026-10-06）

- 空会话以「先来一题」替代四张固定建议卡；保留篝火、法师、深色像素描边、硬阴影与余烬金，入场使用阶梯动效。题干浮现后选项依次展开；减少动态效果时立即可答。
- v0.2.174 在两侧留白加入可点亮的暗塔营灯与遗迹，入场经场景揭幕、符文聚拢与题目凝成；不额外召题，不在已有对话播放。详见 [CAMPFIRE-ARRIVAL-SPEC](CAMPFIRE-ARRIVAL-SPEC.md)。
- 每次进入空会话、切换空会话、改变应试范围或点「换一道」都现场调用模型生成一题。请求开始立即移除旧题；不读取历史题组、不缓存题目、不用固定题兜底。动画只在本次完整结果到达后开始。
- `POST /api/chat/opener`：入参 `{ exclude?: string[] }`（最多 8 个、每个最多 400 字的近期题干）；返回 `{ id, question: { topic, question, options, answer, explanation }, scope }`。范围与专注方向由服务端按登录归属读取，不信客户端自报；模型输出必须有 2–4 个不同选项与一个有效答案下标，不能依赖外部图表材料。重复近期题干不交付，最多修复一次，仍重复即明确报错。
- 此开场题不创建会话、不落聊天历史、不写学习战绩。选答案在当前页揭示解析；「聊聊为什么」携带完整题目、所选答案和解析作为首问，走现有 quick-start 路径。直接输入问题始终可用。
- 卷轴所有字段以纯文字展示；代码仅允许短行内表达式。模型返回的代码围栏必须拒绝并重新出题，不能把原始格式标记交付给学习者。
- 加载只显示召题状态与像素符文，不显示任何旧题内容。失败显示原因与「重新召题」；请求取消、卸载和晚到的旧响应不能改写当前题。响应 `Cache-Control: no-store`，每次调用带独立随机种子；近期题干仅作排重，不保存可回显的题目缓存。服务端按用户在 `app_settings` 保存最近 8 个题干的 SHA-256 摘要，刷新后也不交付重复题干；原题、选项与答案不落此记录。
- 初始应试范围读取结束后才召题；范围读取最多等 5 秒，失败也结束等待（实际范围仍由服务端读取）。首次回答和一次修复共用 40 秒，客户端等 45 秒，与引路灯共用预算。初始输出上限 2048 token；截断后只在剩余预算内提高到 4096 token 重创作一次，再失败如实报错。所有取消仍记取消，不拿旧题充成功。
- 与引路灯共用 JSON 提取：原样解析优先，只转义确定非法的字符串内引号和反斜杠，不猜含糊边界、不补截断内容。所得题仍须通过完整校验与排重。
- 开场热身优先考基础定义或一步运算，选项不写 A/B 标签；题干、选项或解析带多行数值矩阵、数值对角矩阵例子时，共享校验拒绝并重新创作，避免复杂计算挤入首次开聊。解析围绕定义或题干已有数字，不追加新的数值矩阵例子。此限制不影响正式题组。
- 交付前由题解角色独立核对每个选项、唯一正确答案与解析；明确通过才交付。发现多解、错答案或错解析时，把具体错因回喂重新创作一次。出题、核对和重创作共享同一 40 秒总预算；核对未完成也不把未核对题当成功。核对用途独立记为 `chat.opener.check`，历史失败记录保留。

## 3. 刻意不做

- **↑ 键编辑上一条提问**：编辑态在 `MessageRow` 内部，跨组件联动的收益配不上复杂度。
- **`beforeunload` 拦关页**：生成在服务端继续、刷新后由 `/live` 对账接回，拦人反而多余。
- **草稿持久化**：见 2.3。
- **系统通知**：见 2.4。
- **对中间某条重试 / 分叉**：与「重新生成只给最后一条」同一条口径（分叉牵扯历史改写）。
- **建议卡先填后发的旧路径不保留开关**：一张卡两种行为（填 / 发）会让人猜；要改提示语再发，新会话开出来后编辑重发（v13）就在那里。
- **暂存持久化**：刷新页面丢掉正在开会话的那一问——与草稿同口径（2.3）。

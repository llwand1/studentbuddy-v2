# 回答自动提炼为练习（v0.2.171）

回答完成并成功落库后，从 CORE / ROUTE / STEP / EXAMPLE / PITFALL / CHECK 学习结构提炼 1 道回忆/解释练习。回答底部仅显示「本次回复已提炼为可练习的题目」，不主动展开题卡、不抢阅读注意力。用户说「考我 / 出题 / 来一道练习题」或使用空主题、未联网的一键出题时，直接取用已提炼的题目。

## 提炼依据

- 优先采用 CHECK 中实际存在的、自包含的自检问题；没有问题时，CORE 转为核心含义与关键性质的解释题，ROUTE 转为保留原题条件的重做题，或关键步骤与依据的复述题。
- 参考要点取自已显示的回答，保留独立步骤正文、表格、验算结果与误区；忽略代码/SVG 围栏内的假标记。相同参考段去重。
- 每次默认 1 道解答题，标「基础题 / 由本次回复提炼的回忆练习」。使用现有题卡、参考对照、AI 阅卷及作答记录；没有新建题库产品线。
- 本阶段是检索练习，不改数字编新变式，不生成未验证的选择题干扰项。参考正确性依赖原回答，不能把它称为真题或独立验算过的答案。
- 需要完整、足够长、有可识别主题的核心/路线正文。寒暄、停止、中断、工具预算不足、GrillMe、过大回复和不足以提炼的短卡不显示承诺。未结构化回复继续沿用现有出题引擎。

## 关联与入口

迁移 v57 的 `reply_practice` 用 `message_id` 关联原回答，外键级联删除；`source_hash` 校验原文一致，源文被修改时缓存失效。重新生成和编辑重发删除原回答时，提炼题一起删除。

仅取当前会话最新的实质回答，跳过工具空行、题组和情景登记行；新回答没有提炼题时不退回旧题。已完成的新知识主题因此不会串到前一个主题。会话归属与软删除在所有读/交付入口核对。

`done.replyPractice` 和历史 `replyPractice` 只带 `{messageId,title}`。提示由服务端真实缓存生成后才发布，不改回答正文，实时和历史同源。

- `POST /api/quiz/from-reply {sessionId}`：有题即广播并落历史题卡，返回 `{available:true,quizId}`；当前回答无题返回 `{available:false}`，客户端再走既有出题管道。非法参数 400，不存在/不归属/已删除会话 404。
- 简短明确的正向「考我」请求在同会话串行链路中直接交付，不开始模型调用。否定、指定新主题、多题、指定题型、真题和 GrillMe 请求保留现有流程。
- `generate_quiz.fromReply=true`：AI 明确要按刚才讲解练 1 题时可以取用；`count>1` 或 `search=true` 继续原引擎。工具仍遵守两阶段写，回灌不含答案。
- 手动选择新的主题、回答风格、联网搜索时，一键出题保留原管道。

提炼是本地解析与 SQLite 写入，不增加每条回答的 LLM 请求、重试任务或 `llm_call` 统计。原有回复后抽词与记忆压缩仍照常运行；用户作答后已有 AI 阅卷可能调用模型。

## 开源参考与取舍（2026-10-09）

| 项目 | 现有做法 | 对 StudentBuddy 的参考价值与限制 |
|---|---|---|
| [Anki 卡片模板](https://docs.ankiweb.net/manual/templates/intro) | 用笔记字段确定卡片正反面及哪些卡片应生成 | 最适合借鉴「一个知识来源派生练习」及内容/展示分离；可不用模型重复生成。模板本身不理解知识含义，题型变化和迁移题需要另行设计。 |
| [Obsidian Quiz Generator](https://github.com/ECuiDev/obsidian-quiz-generator) | 从选定笔记用模型生成多类题，保存为 Markdown callout 或复习格式，重新打开题目做练习 | 借鉴材料与保存题分离、结构化格式共用渲染；丰富题型是优势。直接照搬每次回答后的生成调用，会增加费用、失败机会和等待，且其主要入口是用户手动选择笔记。 |
| [Open QuizUI](https://github.com/axel-chamberland/Open-QuizUI) | Open WebUI 工具/消息下方 action 展示交互选择题，支持编辑、数学与答后解析 | 借鉴在聊天里用真实可作答 UI，而不是文本题单。其 action 需要用户触发，格式错误会影响解析；嵌入 HTML 和宿主依赖不适合直接替换现有像素题卡。 |

以上是对公开文档的架构比较与适配判断；未复制三者代码，未宣称它们已实现本产品要求的无感、逐回答自动提炼。

本次选用 Anki 式派生关系 + StudentBuddy 已有语义回答结构。优势是快速、可溯源、少一次 AI 调用；限制是默认回忆/解释题，覆盖与变化比专门模型出题少。以后若需要变式，可在用户明确要不同题型时交给现有出题管道，避免先为每条回答产生一批没人使用的题目。

## 验证

自动验证覆盖真实聊天完成→缓存→done 提示→考我复用、真实 HTTP 出卡/历史/作答、账号隔离、原文改变/删除、新回答不回退旧题、题意分流及围栏边界。浏览器核对提示、直接出卡、答前隐藏参考、手机排版和历史回看；发布前跑现有完整检查与构建。

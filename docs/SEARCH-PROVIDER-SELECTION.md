# SEARCH-PROVIDER-SELECTION — 托管搜索 provider 选型建议

> 版本：v0.1.0 | 状态：[建议待批] | 更新：2026-09-25
>
> 本册只回答一个问题：**生产 `.env` 里该配哪一家托管搜索 provider 作为平台默认**。
> ★ **它是建议，不是既成事实**：全文**没有申请任何 key、没有碰过生产 `.env`、没有发版**。
> 落地那一步（申请 key → 写进 `/opt/studentbuddy/app/.env` → 重启服务）逐次要老板点名，
> 因为那是生产写操作。
>
> 触发点：issue #11（免 key 的 Bing 通道因上游改版静默哑掉）建议 4——「给默认部署配一个有 key 的
> provider 作主通道，免 key 通道退为兜底」。当时我把整条链路的**形状**修好了（`bing-channel.ts`
> ＋形状不符即报错＋真网络探针），但形状好不等于有额度：**当前线上仍然只有那条免 key 的借用入口在
> 承重**，而它的可用性由别人的改版决定。

---

## 1. 决策口径（先说清"按什么判"，否则后面每个数字都可以被重新排列组合出别的结论）

按权重从高到低，四条：

1. **免费额度能不能覆盖我们的真实用量**——现在 6 个注册用户、真人流量接近零（口径见
   `docs/metrics-product.md`），所以"能不能免费跑"压倒"哪家结果更聪明"。
2. **代码今天接不接得上**——三家适配器的形状是否仍然符合各家**现行** API。不符的那家不能当默认。
3. **失败时我看不可看见**——这条是 issue #11 的学费：静默零结果比直接报错贵得多。
4. **额度爆了谁付**——按量计费的天花板必须可预期，不能一个异常月份刷出一张没见过的账单。

⚠️ **一条容易被忽略的架构事实（决定了"配几家"而不是"配哪几家"）**：
`searchWeb()` 把**所有拿到 key 的 provider 并行发出去**再聚合（`search/index.ts` 的 `IMPL` 并发段）。
⇒ **配两家就是两笔账单、两次限速消耗，而收益只是结果集更宽**。
本册因此建议 **`.env` 只配一家**；其余两家继续留给用户自带 key（BYOK）那条路。

## 2. 现状事实（全部现读实测，不是推断）

| 事实 | 读数 | 怎么读出来的 |
|------|------|--------------|
| 生产 `.env` 里的搜索 key 条数 | **0** | 只读 `grep -cE "^(EXA_API_KEY\|TAVILY_API_KEY\|ZHIPU_API_KEY)=" /opt/studentbuddy/app/.env` ⇒ `0`（该文件共 19 行、14 个变量名，含 `SB_PLATFORM_API_KEY`＝聊天侧平台 key **是配着的**） |
| 线上实际用的搜索通道 | **只有 `bing`** | 生产机上跑 `tools/probes/bing-channel-live.mjs` ⇒ `providers:["bing"]`、8 条结果、`failed:[]` |
| 三家托管 provider 是否真跑过 | **一次都没有** | 上一行＝0 条 key ⇒ 三家永远不进候选；`docs/dev/test-plan.md` 里 Exa 高亮回灌那条也标着「未核对」 |
| 线上搜索现在是坏的还是好的 | **形状已修、发版未做 ⇒ 仍是坏的** | 修法在 `main`（PR #14 已合），但 `deploy.sh` 未跑（发版逐次点名授权） |

★ **顺带修掉的一个前置坑（本册的推荐依赖它）**：`getProviderKey()` 以前是 **env 覆盖用户 BYOK**，
而注释与契约 §8.2 写的是"env 是平台兜底"。顺序不倒过来，"配一家平台 key 到 `.env`"这个动作
本身就会**静默绕过全站用户自己填的 key**（他花不到自己买的额度，也删不掉那盏「已配置」的灯）。
现已按 issue **#16**（`bug-ledger` **B-020**）修正，并带 4 条断言"外呼真正带出去哪把 key"的回归锁。
⇒ **先合 #16，再配 key**，顺序反了就会咬人。

## 3. 三家对照（取数日期一律 **2026-09-25**；★ 带「未证实」的格子不许当决策依据）

| 项 | **Tavily** | **Exa** | **智谱 BigModel** |
|----|-----------|---------|------------------|
| 免费额度 | **1,000 credits/月**，每月重置；basic 搜索＝1 credit ⇒ 约 **1,000 次/月** | **每月 US$10 免费额度**，页面写「不需要支付方式」；按 $7/1k 折算约 **1,400 次/月** | **未证实**（官方文档只列每次单价，未见注册赠送额度；未登录看不到，故按 **0** 保守处理） |
| 拿免费额度要不要信用卡 | **不要** | **不要**（同上，来自其 pricing 页文字） | 人民币充值制，无"免费档"概念可对 |
| 按量价 | basic **$0.008/credit**（≈ **$8/1k**）；advanced＝2 credits | 实时搜索 **$7/1k**；deep **$12–15/1k**；contents $1/1k 页 | `search_std` **0.01 元/次**（¥10/1k）；`search_pro` **0.03 元/次**（¥30/1k）；搜狗/夸克引擎 0.05 元/次 |
| 100 次/日的月成本 | 免费档基本全覆盖 ⇒ **≈ $0**（超出部分 ≈ $16） | 免费 $10 抵掉后 **≈ $14/月** | **≈ ¥30/月**（std） |
| 1,000 次/日的月成本 | **≈ $232** | **≈ $210** | **≈ ¥300/月**（std）＝三者最便宜 |
| 免费档限速 | **100 RPM**（Dev 档） | **未证实**（公开文档未给免费档 rpm） | **未证实** |
| 端点/鉴权与代码是否相符 | ✅ 相符（`POST api.tavily.com/search`＋`Bearer`，`max_results`/`search_depth`/`results[].content` 均为现行形状） | ✅ 相符（`POST api.exa.ai/search`＋`x-api-key`；`contents.highlights` 仍支持） | ⚠️ **不符**：文档写请求字段是 **`search_query`**（另有可选 `search_engine`），代码发的是 **`query`**。已在 `zhipuSearch` 上方留注说明**为什么本批不盲改**（见 §5） |
| 中文查询结果质量 | 全球/英文偏重的索引，中文可用但非强项（第三方比较口径，★ 无官方声明＝**未证实**） | 神经检索、**英文/全球偏重**，中文普遍偏弱（同上，**未证实**） | **中文最强的一项**：走国内索引（百度/搜狗/夸克引擎），这是它唯一的实质优势 |
| 从本仓生产机（美国 VPS）可达性 | 美国 SaaS，直连 | 美国 SaaS，直连 | `open.bigmodel.cn` 为中国侧部署 ⇒ 美国出口打它是这几家里**最可能慢/被限的一跳**（**未证实**，只是方向判断） |
| 免费档能否用于**生产/商用** | **未证实**（★ 本册最大的一条前置条件，见 §5） | **未证实** | 国内合规实名/备案口径，未读其免费商用条款 |

★ **一条把"用户在墙内"这个直觉排除掉的事实**：三家 provider 都是**服务端调用**，用户浏览器从不直连它们。
⇒ 「中国大陆能不能访问 Tavily」这个问题**与决策无关**，要问的只有「我们那台美国 VPS 的出口能不能」。
反而智谱是反向风险：中国的服务器在中国，我们的出口在美国。

**只作对照、代码暂不支持的两家**（不建议本批引入，除非上表三家全否）：
- **Brave Search API**：免费额度与是否要卡＝**未证实**（pricing 页 JS-only，两次抓取都失败）；返回的是 SERP 链接而非"给 LLM 用的正文片段"，要新写适配。
- **Serper.dev**：注册送 **2,500 次**、页面写「No credit card required」；但它是 **Google SERP 抓取器**，生产化 LLM 用途的条款风险与我们刚踩过的免 key Bing 通道**同一类**——用它当默认＝把可用性问题换个上游再存一遍。

数据来源（逐条可复核）：
- Tavily：`docs.tavily.com/documentation/api-credits`、`tavily.com/pricing`、`docs.tavily.com/documentation/rate-limits`
- Exa：`exa.ai/pricing`、`exa.ai/docs/reference/pricing`、`exa.ai/docs/reference/search`
- 智谱：`docs.bigmodel.cn/api-reference/工具-api/网络搜索`、`docs.bigmodel.cn/cn/guide/tools/web-search`
- Serper：`serper.dev/`；Brave：其 pricing 页取数失败（记为未证实）

⚠️ **取数方式如实记**：以上数字由**公开文档页在 2026-09-25 的读数**整理，**没有一把真 key 打过真请求**
（我们没有 key）。所以"1,000 credits/月"这类是**页面声明**，不是**我们实测到的账户行为**。
落地时第一件事应当是在控制台核对自己拿到的实际额度。

## 4. 三个候选各自的"坏法"（选型时我最在意的不是谁更强，是谁坏了会叫我）

| provider | 坏了长什么样 | 本仓现在能不能看见 |
|----------|--------------|--------------------|
| 免 key Bing（现状） | 上游改一次重定向 ⇒ 全站 0 结果，且**报的是"空结果"不是"失败"** | ✅ 已能看见（B-019 那批加了形状判据＋`tools/probes/bing-channel-live.mjs`，退出码可给 cron） |
| Tavily / Exa（配 key 后） | 401（key 失效）／429（限速）／额度耗尽 ⇒ `!res.ok` **直接抛错** | ✅ 会进 `failed` ⇒ 落到 `search_empty` 事件里；但**额度余额本身没人盯**，需要人工看控制台（⚠️ 未做：余额告警） |
| 智谱（当前代码） | 字段名对不上 ⇒ **4xx 或空结果**，而失败被"单家失败跳过"吞掉 | ⚠️ 三家并行时它坏了不影响别的家 ⇒ **最坏的一种：永远坏着且没人知道** |

## 5. 建议

**主：Tavily，配进 `.env` 的 `TAVILY_API_KEY`（一家，别配两家）。**
**备选：Exa（`EXA_API_KEY`）**——若将来更看重"结果直接喂模型的内容质量"或 Tavily 条款不合。
**智谱：不进 `.env`**，并单列一批"拿 key 实跑一次＋改 `search_query`"，两件事**必须同批**做。
★ 不做"实跑"就改字段名，等于把唯一能证伪它的线索也改掉——本批已在 `zhipuSearch` 上方留注记录该判断。

**决定它的三个数字**：
1. 我们的量在免费档里：**1,000 次/月** 对 6 个用户 ⇒ 正常月份 **$0**，而 Exa 是"送 $10 额度"，
   异常月份会以美元计进来（更不可预期）。
2. **代码今天就能跑**：Tavily 形状与实现相符，智谱不符。
3. **限速余量**：100 RPM 对当前并发（闸门封顶 12）绰绰有余；Exa 免费档 rpm **未证实**。

★★ **但这一条推荐有一个必须先读的前置条件，读不通就翻案**：
Tavily **免费档是否允许生产/商用**——我**未证实**（没读条款原文，只读了 pricing 与 docs 页）。
若其免费档限定非商用，决策应立刻切到 Exa（同样是"AI agent 用途"定位、且明确写不需要支付方式）。
⇒ 落地清单第 0 步就是读这一条，别跳过。

## 6. 落地清单（要老板逐次点名的都在这一步，本册不代做）

0. 读 Tavily 现行条款里"free tier / production / commercial use"那一段（判据：能否商用＝是否继续本册推荐）。
1. 申请 key（Tavily 控制台），**不写进仓库任何文件**；本机也不建 `.env`。
2. 生产写：把 `TAVILY_API_KEY=<key>` 加进 `/opt/studentbuddy/app/.env`（现读 19 行 ⇒ 追加一行），
   `systemctl restart studentbuddy`。⚠️ 这会重启服务、踢掉在途会话，属生产写操作。
3. 验证（★ 用占位符，任何文档/台账/提交里都不许出现真 key）：
   ```bash
   curl -sS -w '\nHTTP %{http_code}  time=%{time_total}s\n' \
     https://api.tavily.com/search \
     -H 'Content-Type: application/json' \
     -H "Authorization: Bearer $TAVILY_API_KEY" \
     -d '{"query":"学生综合素质评价 政策 2026","max_results":6,"search_depth":"basic"}'
   ```
   判据：HTTP 200 **且** `.results` 非空、每条 `title`/`url`/`content` 都非空串。
   ★ **必须看中文那一句的结果内容**，不接受"200 就算通"——issue #11 的学费正是"状态码通、内容是空"。
   再加一道：控制台里 credit 计数**恰好 -1**（basic＝1 credit），对不上就说明计费口径与文档不同。
4. 应用侧再验一遍：走一次真实对话，确认 `search_web` 的 `failed:[]`、`providers` 里出现 `tavily`
   （免 key Bing 此时退为**兜底**，只有 tavily 失败才该看到它）。
5. 真人那一遍（§0.16）：配完之后必须有人**在应用里搜一句、读一眼结果有没有出处**，探针绿不算。
6. 可选（建议同批）：给 `tools/probes/` 加一条带 key 的托管通道探针，把"额度耗尽/401"变成 cron 能喊的东西。

## 7. 未做 / 未验（本册交付时如实为空的部分）

- ⚠️ 没申请任何 key、没读过任何一家控制台的**实际**额度与计费页（无账号）。
- ⚠️ 三家 provider 的**响应内容质量**没有一次真实数据可比；中文质量那一行是文档/第三方口径，**未证实**。
- ⚠️ Tavily/Exa 免费档的**商用许可条款未读原文**＝§5 那条前置条件成立与否未定。
- ⚠️ Brave 取数失败（页面 JS-only），未做完整对比；本批也没为它写适配器（未开工）。
- ⚠️ 没做余额告警、没做 provider 熔断（一家连续失败就暂时不再调用）。
- ⚠️ 智谱 `search_query` 的差异**只登记未修改**（理由见 §5）。
- ⚠️ 本册所有数字**取数于 2026-09-25**，价格与免费额度是这类服务最容易变的部分——引用前先复扫。

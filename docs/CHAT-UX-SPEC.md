# 对话体验（Chat UX）——流式期与常用动作的口径

> 版本：v0.1 | 状态：[活跃] | 新建：2026-09-28（分支 `feat/chat-ux-polish`，叠在 `fix/chat-grimoire-review` 之上）
>
> 本册管的是对话页**流式 UI 与常用动作**的行为口径：错误后怎么重来、键盘怎么停、草稿怎么留、离开标签页怎么知道回答好了、选中一句怎么追问。
> 它不改 SSE 帧（`docs/SSE-CONTRACT.md` 不动）、不改服务端、不加路由、不落库；视觉语言沿用 `docs/PIXEL-UI.md` 的篝火对谈小节。

## 1. 为什么要有它

对话页的流式底座已经齐了（`useChatStream` 的 SSE 重连与 `/live` 对账、`stream-smooth.ts` 的逐字排空、`useScrollAnchor` 的贴底/离底、思考／任务／工具三块过程面板）。缺的是**围绕它的几个日常动作**：

| 场景 | 改版前 | 问题 |
| --- | --- | --- |
| 上游超时 / 断流 / 点了停止 | 只出一条 `⚠ 生成失败：…`，那一轮**没有助手消息** ⇒ 连「重新生成」按钮都没有 | 重来要把问题再打一遍 |
| 生成中想停 | 只能用鼠标去够停止键 | 焦点本来就在输入框 |
| A 会话打了半句去 B 看一眼 | `input` 不随会话切换 ⇒ 半句话跟到 B 的输入框，切回 A 是空的 | 发错会话 / 丢草稿 |
| 长回答切去别的标签等 | 标签页标题没有任何变化 | 不知道好了没有 |
| 离底时底下还在长 | 「回到最新」与看历史时长得一样 | 没有「新内容」信号 |
| 点按钮发送 | 焦点留在按钮上 | 下一句要先点回输入框 |
| 「这句没懂」 | 手抄或整段复制粘贴 | 学习对话里最常见的追问动作没有入口 |

## 2. 行为

### 2.1 错误条「↻ 重试」（`ChatErrorBar.tsx`）

- 错误条承载两类错误：**流式中断**（SSE `chat-error` 帧：上游错／超时／`已停止`）与**发送失败**（HTTP 层，`sendError`）。
- 只有前者给「↻ 重试」：那一问已经进了会话，重试＝**对最后一问重新生成**（走既有 `regenerate()`，服务端 `POST …/regenerate`，会保留到最后一条用户消息）。
- 不给的情形：生成中（`busy`，已经在跑）；会话里没有用户消息（没有可重跑的对象）；发送失败（那条提问压根没进会话，改一改再发即可）。
- 点「停止」后留下的半截回答 `（已停止）` 与 `⚠ 已停止` 错误条一起出现——**这是既有口径**，本册只给它一个出口。

### 2.2 Esc 停止（`ChatComposer.tsx`）

- 输入框聚焦、`busy` 为真时按 `Escape` ＝ 点停止键（`onStop`），并 `preventDefault`。
- 不忙时 Esc 什么都不做；输入法组字期间（`isComposing`）的 Esc 属于输入法，不拦。
- 忙态占位文案改为「生成中…（Esc 停止）」——快捷键要**在它能用的地方写出来**。

### 2.3 草稿按会话隔离（`useSessionDraft.ts`）

- 切走：当前输入存到旧会话名下；切到：取新会话的草稿，没有就空。
- 唯一例外：从「无会话」切到刚开的新会话且输入框非空——建议卡 `pick()` 是先填字再开会话，那半句话原样带过去。
- **只存内存**（`ref` 里的 `Map`）：刷新页面不保留。草稿是「这一坐」的上下文，不做持久化、不做跨端。
- 既有的「切会话清附件 / 收起载入面板」不变。

### 2.4 标签页标题（`useBusyTitle.ts`）

- 生成中：`document.title` 前缀「● 回复中 · 」；前台完成 ⇒ 复原。
- 后台完成（`document.hidden`）⇒ 前缀「✓ 回答完成 · 」，直到 `visibilitychange` 切回前台再复原。
- 只在「忙过」之后动标题；忙态中途卸载（切页）复原；再次进入忙态先清掉上一段「完成」态——**不叠前缀**。
- 只改标题，**不发系统通知、不响铃**（要授权、也过重）。

### 2.5 离底提示（`ChatComposer.tsx` / `chat-extras.css`）

- 离底且 `busy`：跳底按钮文案「↓ 新内容」＋ `.live`（前面一颗 `steps(2)` 眨的余烬点）；不忙时仍是「↓ 回到最新」。
- 顺手修正：`.chat-jump` 此前 `inline-flex + margin:auto` 从未真正居中，改块级 `flex + fit-content`。
- `prefers-reduced-motion: reduce` 下不眨。

### 2.6 发送后焦点回输入框（`ChatView.tsx` `submit()`）

- 点发送按钮后 `inputRef.current?.focus()`；Enter 发送本来就在输入框里，不受影响。

### 2.7 引用追问（`QuoteAsk.tsx` + `quote-ask.ts`）

- 只认**助手正文**（`.chat-row:not(.user) .chat-bubble.md`，含流式中的气泡）里的选区；用户自己的话、过程面板、题卡里的字都不算。
- 选区侦测：`selectionchange` 去抖 180ms（统一覆盖鼠标拖选、Shift+方向键、触屏拉柄）；至少 2 个非空白字符才算；塌缩 ⇒ 收起；小牌之外 `mousedown` ⇒ 收起；消息流滚动 ⇒ 收起（fixed 定位不跟着选区走）。
- 小牌 `↩ 引用追问` 用 `position: fixed`，横向取选区中点、纵向贴选区底边 +8px；坐标写成元素上的 CSS 变量 `--qa-x/--qa-y`（`style.setProperty`，不走内联 JSX style——门禁红线）。
- 点击：`buildQuote(text)` 逐行加 `> `、丢空行、行内连续空白折成一个空格、超过 `QUOTE_MAX_CHARS = 300` 截断加 `…`；`mergeQuoteIntoInput` 空框 ⇒ `引用块\n\n`，已有内容 ⇒ 接在其后空一行（**不覆盖**打了一半的问题，函数式 `setInput`）；随后聚焦输入框、清掉选区。
- 引用块作为普通 Markdown 进入用户消息（用户气泡按原文显示 `> …`），服务端不做任何特殊处理。

## 3. 刻意不做

- **↑ 键编辑上一条提问**：编辑态在 `MessageRow` 内部，跨组件联动的收益配不上复杂度。
- **`beforeunload` 拦关页**：生成在服务端继续、刷新后由 `/live` 对账接回，拦人反而多余。
- **草稿持久化**：见 2.3。
- **系统通知**：见 2.4。
- **对中间某条重试 / 分叉**：与「重新生成只给最后一条」同一条口径（分叉牵扯历史改写）。
